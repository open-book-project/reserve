    Unit 4: Database: MySQL Connectivity¶

    A form handler that forgets everything the moment it replies is not yet an application. This unit adds the memory: a relational database, MySQL, and the small set of PHP functions that send SQL to it and bring rows back. It teaches the SQL statements for creating a database and its tables and for the four operations on data (create, retrieve, update and delete), then connects PHP to MySQL, builds a complete CRUD application, and ends with the most important security lesson of the course, SQL injection and the prepared statement that prevents it.

    It corresponds to Unit 4 of the course, Database: Connectivity with MySQL, which is allotted 15 lecture hours, the largest share of the course.

    Learning outcomes

    • Create a database and tables with sensible column types, a primary key and AUTO_INCREMENT.
    • Write INSERT, SELECT, UPDATE and DELETE statements, including WHERE, ORDER BY, LIMIT, GROUP BY and JOIN.
    • Connect PHP to MySQL with mysqli, in both the procedural and the object style, and report a failure properly instead of showing a blank page.
    • Loop over a result set and turn it into an HTML table.
    • Insert what a form submitted, and update or delete an existing row.
    • Explain SQL injection, demonstrate it, and stop it with a prepared statement.

    4.1 Why a web application needs a database¶

    The idea, first

    Unit 3 built a registration form. Submit it and the data is gone the instant the reply is sent: nothing on the server remembers it. You could write the values to a text file, and for about a week that would work — until two people submit at the same moment, or you want the students from Delhi with more than 70 marks sorted by name, or somebody's name contains a comma.

    A database solves all three at once. It stores rows in tables with declared types, answers questions about them in a language designed for questions, and handles simultaneous writers without you thinking about it. SQL is that language, and MySQL is the program that speaks it — the M in XAMPP, and the one the course names.

    So there are two skills here, and they are worth keeping separate in your head. SQL is a language you write and test in phpMyAdmin, with no PHP anywhere near it. Connectivity is the small set of PHP functions that send a string of SQL to MySQL and hand back the rows. Almost every problem a student has in this unit is actually a broken SQL string, and the fastest way to find that out is to paste the query into phpMyAdmin and watch MySQL say why.

    The sample database

    The examples in this unit use a small college database with seven students and four courses; its definition is given in Section 4.3. The outputs shown were produced by running the statements and programs against that data, in the order in which they appear, so a statement that changes the data (such as the INSERT in Listing 4.3) is reflected in the listings after it, until the data is put back to the original seven students after Listings 4.9 and 4.10. Every PHP program of this unit starts from the original seven students.

    4.2 The relational model, in one page¶

    Word Means In our database
    Database a named collection of tables college
    Table rows all of the same shape students, courses
    Row / record / tuple one thing one student
    Column / field / attribute one property, with a declared type marks INT
    Primary key the column that identifies a row uniquely; never repeated, never null roll
    Foreign key a column holding another table's primary key students.course → courses.code
    NULL "no value recorded" — not zero, not the empty string a student with no email yet
    Index a lookup structure that makes a WHERE fast created automatically for the primary key

    Choosing a column type¶

    Type Holds Use for
    INT a whole number, about ±2 billion roll numbers, marks, counts
    BIGINT a much larger whole number phone numbers stored as numbers — though see below
    VARCHAR(n) text up to n characters, stored compactly names, emails, and phone numbers — a leading zero must survive, and you never do arithmetic on a phone number
    CHAR(n) exactly n characters, padded fixed codes: a state code, Y/N
    TEXT long text, up to 64 KB an address, a comment, an article
    DECIMAL(8,2) an exact number with 2 decimal places money — never FLOAT, which cannot represent 0.10 exactly
    FLOAT / DOUBLE approximate measurements, averages
    DATE YYYY-MM-DD date of birth
    DATETIME / TIMESTAMP date and time when a row was created
    BOOLEAN really TINYINT(1): 0 or 1 is_active
    ENUM('a','b') one of a fixed list gender, status
    Constraint Means
    PRIMARY KEY unique and not null; one per table
    AUTO_INCREMENT MySQL fills it in, one higher each time
    NOT NULL a value must be supplied
    UNIQUE no two rows may share it — an email column wants this
    DEFAULT x used when the INSERT omits the column
    FOREIGN KEY … REFERENCES the value must exist in the other table

    4.3 Database creation and creating tables¶

    With phpMyAdmin¶

    1. Start Apache and MySQL in XAMPP, then open http://localhost/phpmyadmin/.
    2. New in the left sidebar → name the database college → collation utf8mb4_general_ci → Create.
    3. Choose the database, then the SQL tab, and paste the CREATE TABLE below. Do it this way rather than through the form: the statement is what you will be examined on, and it is what you can save in a file and re-run.

    schema.sql

    CREATE DATABASE IF NOT EXISTS college;
USE college;

CREATE TABLE students (
    roll    INT          PRIMARY KEY,
    name    VARCHAR(50)  NOT NULL,
    course  VARCHAR(10),
    marks   INT          DEFAULT 0,
    email   VARCHAR(60)  UNIQUE,
    city    VARCHAR(30)
);

    The definition used for the examples in this unit. Note the trailing semicolon on each statement — phpMyAdmin needs it when you paste several at once.

    AUTO_INCREMENT is what you want for most keys

    Operator Example Matches
    = <> < > <= >= marks >= 60 the obvious

    Aggregates and GROUP BY¶

    An aggregate function turns many rows into one number. GROUP BY says "do that once per group" instead of once for the whole table.

    Function Gives Note
    COUNT(*) how many rows counts rows, nulls and all
    COUNT(email) how many rows have a non-null email the difference between the two is the number of nulls
    SUM(marks) the total ignores nulls
    AVG(marks) the mean ignores nulls, which is usually what you want
    MIN / MAX smallest / largest works on text too

    Listing 4.7. GROUP BY, with and without HAVING

    SELECT course,
       COUNT(*)          AS students,
       ROUND(AVG(marks)) AS average,
       MAX(marks)        AS best
FROM students
GROUP BY course
HAVING COUNT(*) > 1
ORDER BY average DESC;

    Result:

    +--------+----------+---------+------+
| course | students | average | best |
+--------+----------+---------+------+
| BCOM   | 2        | 81      | 88   |
| BAECO  | 2        | 73      | 91   |
| BSCCS  | 4        | 65      | 82   |
+--------+----------+---------+------+
3 rows in set

    WHERE filters rows before grouping; HAVING filters groups after. That single sentence answers most exam questions on this topic.

    JOIN: reading two tables at once¶

    students.course holds a course code. The readable title lives in courses. A join brings them together for one query, without ever storing the title twice.

    Listing 4.8. INNER JOIN and LEFT JOIN

    SELECT s.name, s.marks, c.title, c.fee
FROM students s
INNER JOIN courses c ON s.course = c.code
WHERE s.marks >= 70
ORDER BY s.marks DESC;

SELECT c.title, COUNT(s.roll) AS enrolled
FROM courses c
INNER JOIN students s ON s.course = c.code
GROUP BY c.title
ORDER BY enrolled DESC;

    4.6 U and D — UPDATE and DELETE¶

    The WHERE clause is not optional

    UPDATE students SET marks = 0; sets every student's marks to zero. DELETE FROM students; empties the table. There is no undo and no confirmation. The professional habit: write the statement as a SELECT first, look at the rows it returns, and only then change the first word.

    Listing 4.9. Check with SELECT, then UPDATE

    -- 1. look before you leap
SELECT roll, name, marks FROM students WHERE marks < 40;

-- 2. the same WHERE, now doing the work
UPDATE students SET marks = marks + 5 WHERE marks < 40;

-- 3. check
SELECT roll, name, marks FROM students WHERE roll = 2231050;

-- 4. several columns at once
UPDATE students SET city = 'New Delhi', email = 'zoya.khan@ex.ac.in' WHERE roll = 2231045;
SELECT * FROM students WHERE roll = 2231045;

    4.7 Connectivity: PHP talking to MySQL¶

    PHP has three ways to reach MySQL. The course means mysqli, and it has two styles that do the same thing.

    Extension Looks like Verdict
    mysqli procedural mysqli_query($conn, $sql) What most textbooks and exam papers use. Start here
    mysqli object oriented $conn->query($sql) The same extension, shorter to type. Know both — you will meet both
    PDO $pdo->prepare($sql) Works with other databases too, and has the nicest prepared statements. Not in this course, but worth a look
    ~~mysql_*~~ ~~mysql_connect()~~ Removed from PHP in 2015. If a tutorial uses it, the tutorial is at least ten years old and its security advice is too

    The four lines that connect¶

    Listing 4.11. Connect, procedurally

    <?php
$host = "localhost";
$user = "root";
$pass = "";          // XAMPP's default: root with no password
$db   = "college";

$conn = mysqli_connect($host, $user, $pass, $db);

if (!$conn) {
    die("Connection failed: " . mysqli_connect_error());
}

echo "Connected to '$db'.\n";

// Always tell MySQL the character set, or Hindi names come back as ????
mysqli_set_charset($conn, "utf8mb4");

$result = mysqli_query($conn, "SELECT COUNT(*) AS n FROM students");
$row = mysqli_fetch_assoc($result);
echo "It holds {$row['n']} students.\n";

mysqli_close($conn);

    Output:

    Connected to 'college'.
It holds 7 students.

    Giving a database name that does not exist makes the connection report the failure instead of the page silently doing nothing. That die() is the difference between a five-minute bug and a two-hour one.

    Listing 4.12. The same thing, object style

    <?php
$conn = new mysqli("localhost", "root", "", "college");

if ($conn->connect_error) {
    die("Connection failed: " . $conn->connect_error);
}

$result = $conn->query("SELECT name, marks FROM students ORDER BY marks DESC LIMIT 2");

echo "Top two:\n";
while ($row = $result->fetch_assoc()) {
    echo "  {$row['name']} — {$row['marks']}\n";
}

echo "Rows in that result: ", $result->num_rows, "\n";
$conn->close();

    Output:

    Top two:
  Riya Singh — 91
  Meera Joshi — 88
Rows in that result: 2

    Identical behaviour, fewer characters. The rule for reading either: procedural functions take the connection as their first argument; the object style has it as the thing before the arrow.

    Put the connection in its own file

    Every page needs it, and the password should appear once. Save db.php with the four variables and the mysqli_connect, then require "db.php"; at the top of every other page. Leave off the closing ?>, or a stray newline will break header() — exactly the bug from Unit 3.

    A curiosity worth knowing

    A ?> inside a // comment still closes the PHP block. // no closing ?> tag here ends PHP mode at the ?> and sends " tag here" to the browser. The tokeniser looks for the closing tag before it looks for the end of the line. Block comments /* … */ are not affected, so write it that way if you must mention the tag at all.

    Listing 4.13. db.php, and a page that requires it

    index.php

    <?php
require "db.php";      // $conn is now available

}

    The fetch functions¶

    Function Returns one row as Read it with
    mysqli_fetch_assoc($r) an associative array $row["name"] — the one to use
    mysqli_fetch_row($r) a numbered array $row[0]
    mysqli_fetch_array($r) both at once, by default wasteful; pass MYSQLI_ASSOC if you use it
    mysqli_fetch_object($r) an object $row->name
    mysqli_fetch_all($r, MYSQLI_ASSOC) every row at once an array of arrays — handy for json_encode in Unit 5

    Each call returns the next row and moves on; when there are no more it returns null, which is why while ($row = mysqli_fetch_assoc($result)) is the standard loop — the assignment's value is the row, and null ends the loop.

    Listing 4.14. All five fetch styles on one query

    <?php
$conn = mysqli_connect("localhost", "root", "", "college");
$sql  = "SELECT roll, name, marks FROM students ORDER BY roll LIMIT 2";

echo "fetch_assoc:\n";
$r = mysqli_query($conn, $sql);
while ($row = mysqli_fetch_assoc($r)) echo "  {$row['name']} ({$row['roll']})\n";

echo "\nfetch_row:\n";
$r = mysqli_query($conn, $sql);
while ($row = mysqli_fetch_row($r)) echo "  $row[1] ($row[0])\n";

echo "\nfetch_object:\n";
$r = mysqli_query($conn, $sql);
while ($row = mysqli_fetch_object($r)) echo "  {$row->name} ({$row->roll})\n";

echo "\nfetch_all:\n";
$r = mysqli_query($conn, $sql);
print_r(mysqli_fetch_all($r, MYSQLI_ASSOC));

    4.10 SQL injection, and prepared statements¶

    The problem, first

    Building a query by pasting a variable into a string means the user's text becomes part of your program, not just your data. Type an apostrophe into a search box and the query breaks. Type the right sequence of characters and the query does something else entirely — returns every row, ignores the password check, or drops the table.

    Listing 4.18. A login that anyone can walk through

    <?php
$conn = mysqli_connect("localhost", "root", "", "college");
mysqli_query($conn, "CREATE TABLE users (id INT, username VARCHAR(20), password VARCHAR(20))");
mysqli_query($conn, "INSERT INTO users VALUES (1,'zoya','s3cret'), (2,'admin','h4rd-t0-guess')");

// What an attacker types into the form:
$username = "admin";
$password = "anything' OR '1'='1";

// The vulnerable way — string concatenation
$sql = "SELECT * FROM users WHERE username = '$username' AND password = '$password'";

echo "The query that actually ran:\n  $sql\n\n";

$result = mysqli_query($conn, $sql);

if ($result && mysqli_num_rows($result) > 0) {
    $row = mysqli_fetch_assoc($result);
    echo "LOGGED IN as {$row['username']} — with the wrong password.\n";
} else {
    echo "Access denied.\n";
}

    Output:

    The query that actually ran:
  SELECT * FROM users WHERE username = 'admin' AND password = 'anything' OR '1'='1'

LOGGED IN as zoya — with the wrong password.

    The password is wrong, and the login succeeds. Read the assembled query in the output: the ' closes the string early, OR '1'='1' is always true, and -- comments out the rest. Nothing exotic happened; the input simply became code.

    Listing 4.19. The same attack against a prepared statement

    <?php
$conn = mysqli_connect("localhost", "root", "", "college");
mysqli_query($conn, "CREATE TABLE users (id INT, username VARCHAR(20), password VARCHAR(20))");
mysqli_query($conn, "INSERT INTO users VALUES (1,'zoya','s3cret'), (2,'admin','h4rd-t0-guess')");

$username = "admin";
$password = "anything' OR '1'='1";

// 1. the query, with ? where the values go — no variables in the string at all
$sql  = "SELECT * FROM users WHERE username = ? AND password = ?";
$stmt = mysqli_prepare($conn, $sql);

// 2. the values, sent separately.  "ss" = two strings
mysqli_stmt_bind_param($stmt, "ss", $username, $password);

// 3. run it
mysqli_stmt_execute($stmt);
$result = mysqli_stmt_get_result($stmt);

if ($result && mysqli_num_rows($result) > 0) {
    echo "logged in\n";
} else {
    echo "Access denied — the apostrophe was treated as part of the password.\n";
}

// And the honest login still works:
$password = "h4rd-t0-guess";
mysqli_stmt_bind_param($stmt, "ss", $username, $password);
mysqli_stmt_execute($stmt);
echo mysqli_num_rows(mysqli_stmt_get_result($stmt)) ? "The real password works.\n" : "";

    Output:

    Access denied — the apostrophe was treated as part of the password.
The real password works.

    Identical input, and the login fails as it should. The query and the data travelled separately, so the apostrophe was never anything but a character in a password.

    Letter in bind_param Means
    i integer
    s string — use this for anything you are unsure about
    d double (a float)
    b blob, sent in chunks

    The letters must be in the same order as the ? marks, and there must be exactly as many. "issi" means: first value an integer, then two strings, then an integer.

    A placeholder stands for a value, never for a name

    SELECT * FROM ? WHERE ? = ? is not valid. Table names, column names and the direction of an ORDER BY cannot be bound. When those must vary — a sortable table, for instance — check them against a whitelist, exactly as Unit 3 did with the sort parameter.

    Listing 4.20. Whitelisting what cannot be bound

    <?php
$conn = mysqli_connect("localhost", "root", "", "college");

// pretend these came from the URL
$sort  = "marks";
$dir   = "desc";
$minimum = "60";

// column and direction: not bindable, so check them against a list
$allowedSort = ["roll", "name", "marks"];
if (!in_array($sort, $allowedSort, true)) $sort = "roll";
$dir = strtolower($dir) === "desc" ? "DESC" : "ASC";

// the value: bindable, so bind it
$sql  = "SELECT name, marks FROM students WHERE marks >= ? ORDER BY $sort $dir";
$stmt = mysqli_prepare($conn, $sql);
mysqli_stmt_bind_param($stmt, "i", $minimum);
mysqli_stmt_execute($stmt);

echo "Query: $sql\n\n";
$result = mysqli_stmt_get_result($stmt);
while ($row = mysqli_fetch_assoc($result)) {
    printf("  %-14s %3d\n", $row["name"], $row["marks"]);
}

    Two rules: values go in placeholders, names come from a list you wrote. Between them they cover every query you will need on this course.

    What about mysqli_real_escape_string()?

    It escapes quotes for you and it does work, which is why older textbooks teach it. But it must be applied to every single value, every time, and one forgotten call is a hole — while a prepared statement cannot be forgotten halfway. Use prepared statements; know what real_escape_string is, because an exam may ask.

    4.11 Solved problems¶

    Example 4.1: 'My INSERT does nothing and shows no error'

    Problem. A student's registration page runs, the browser shows the success message, and phpMyAdmin shows no new row. Diagnose it systematically.

    Step 1 — is the query even being checked?

    The usual cause is mysqli_query($conn, $sql); with the return value thrown away, followed unconditionally by "Registered successfully". The message is printed whether or not anything happened. Always write if (!mysqli_query(...)) die(mysqli_error($conn));.

    Step 2 — print the SQL and read it

    echo $sql; and look. Nine times in ten the answer is visible: an empty value where a variable should be (the form field's name does not match), or VALUES (, , ), or quotes in the wrong place.

    Step 3 — paste that SQL into phpMyAdmin

    If MySQL rejects it there, the problem is the SQL and PHP is innocent. If MySQL accepts it there, the problem is in PHP — usually the wrong database, or a connection that failed silently.

    Step 4 — the two silent killers

    A NOT NULL column with no default, receiving nothing. And a duplicate primary key — MySQL says "Duplicate entry", but only if you are looking at mysqli_error().

    Answer. Check the return of every query; echo the SQL; run it in phpMyAdmin

    Example 4.2: A name with an apostrophe breaks the page

    Problem. Inserting "O'Brien" produces You have an error in your SQL syntax near 'Brien'. Explain, and give two fixes.

    Step 1 — see the query MySQL saw

    INSERT INTO students (name) VALUES ('O'Brien'). The apostrophe in the name closed the string after O, so Brien' is left over and means nothing. MySQL is right to complain.

    Step 2 — the escaping fix

    mysqli_real_escape_string($conn, $name) turns it into O\'Brien, which MySQL reads as one string containing an apostrophe. It needs the connection, because the correct escaping depends on the character set.

    Step 3 — the real fix

    A prepared statement. The name never enters the SQL text at all, so there is nothing to escape and nothing to forget.

    Step 4 — why this matters beyond Irish surnames

    The same character that breaks the query for an honest user is the one an attacker uses deliberately. A page that cannot store "O'Brien" is a page that can be injected — they are the same bug seen from two sides.

    Answer. Prepared statement; or mysqli_real_escape_string on every value, without exception

    Example 4.3: Paginating a long list

    Problem. A table has 500 students. Show 5 per page, with working "previous" and "next" links.

    Step 1 — the two numbers

    LIMIT $perPage OFFSET $offset, where $offset = ($page - 1) * $perPage. Page 1 has offset 0, page 2 has offset 5. Getting that arithmetic wrong by one is the classic bug.

    Step 2 — how many pages

    A second query, SELECT COUNT(*), gives the total. ceil($total / $perPage) is the number of pages — ceil, because 11 rows at 5 per page needs 3 pages, not 2.2.

    Step 3 — clamp the page number

    $page comes from the URL, so it can be 0, −4 or "abc". Cast it to an integer and force it into range, or the offset goes negative and MySQL errors.

    Step 4 — why not fetch everything and slice in PHP?

    Because that transfers 500 rows to show 5, and at 50,000 rows it exhausts memory. Let the database do the work it is built for.

    Answer. LIMIT n OFFSET (page-1)*n, plus a COUNT(*) for the number of pages

    Example 4.4: Searching, safely

    Problem. Add a search box that finds students whose name contains what was typed. Make it injection-proof.

    Step 1 — LIKE with wildcards

    "Contains" is LIKE '%text%'. "Starts with" is LIKE 'text%', which is much faster on a large table because an index can be used — worth knowing even though it is not what was asked.

    Step 2 — where the % signs go

    Not in the SQL. Bind the whole pattern: $pattern = "%" . $q . "%"; then bind $pattern. Writing LIKE '%?%' in the SQL does not work — the ? inside quotes is a literal question mark, not a placeholder.

    Step 3 — the empty search

    An empty box should show everything, or nothing, but must not error. %% matches every row, which is a reasonable answer.

    Step 4 — and escape it on the way out

    The search term is echoed back into the page ("Results for …"), so it needs htmlspecialchars() — two different defences for two different destinations.

    Answer. Bind "%$q%" as one value; never put ? inside quotes

    4.12 Common mistakes to avoid¶

    • Do not build queries by pasting variables into strings. Use prepared statements — every time, not just for logins.
    • Do not ignore the return value of mysqli_query(). Check it and print mysqli_error($conn) while you are developing.
    • Do not confuse "the query failed" (false) with "the query matched nothing" (num_rows === 0).
    • Do not write UPDATE or DELETE without a WHERE. Write it as a SELECT first.
    • Do not compare with = NULL. Use IS NULL and IS NOT NULL.
    • Do not put a placeholder inside quotes: LIKE '%?%' is a literal question mark. Bind the whole pattern instead.
    • Do not try to bind a table or column name. Whitelist those.
    • Do not store money in a FLOAT. Use DECIMAL(10,2).
    • Do not store a phone number as an INT — a leading zero disappears and you will never add two phone numbers together.
    • Do not put a SELECT inside a loop when a JOIN would do it in one query. Ten students should not mean eleven queries.
    • Do not forget mysqli_set_charset($conn, "utf8mb4") if any name might not be in English.
    • Do not echo a database value without htmlspecialchars(). The database is not a source of trusted text — someone's form put it there.

    4.13 Summary¶

    The key points of the unit, each stated as something you should now be able to do.

    • You can say why a database rather than a file: declared types, a language for asking questions, and safe simultaneous writers.
    • You can name the parts — database, table, row, column, primary key, foreign key, null — and choose a column type on purpose, including the two that are asked about in vivas: DECIMAL for money and VARCHAR for phone numbers.
    • You can create a database and a table, with a primary key, NOT NULL, DEFAULT and AUTO_INCREMENT, and you know why you should paste the statement into phpMyAdmin rather than click through its form.
    • You can write all four CRUD statements, and the whole SELECT in the right clause order, with WHERE, LIKE, IN, BETWEEN, IS NULL, ORDER BY and LIMIT.
    • You can aggregate and group, you know that WHERE filters rows before grouping while HAVING filters groups after, and you can join two tables — including the LEFT JOIN that keeps the rows with no match.
    • You can connect from PHP in either style, check for failure, loop a result set with while ($row = mysqli_fetch_assoc($result)), and turn it into an escaped HTML table.
    • You can write the four-file CRUD application — list, form, save, delete — with validation before the write and a redirect after it.

    Exercise 4.31. Why does mysqli_affected_rows() return 0 after an UPDATE that set a column to the value it already had? When would that matter?

    Answer

    By default MySQL reports the number of rows that were actually changed, not the number that were matched by the WHERE clause. An UPDATE that writes the value a column already holds changes nothing, so the count is 0 even though the row was found.

    It matters when a program treats 0 as "no such record". A user who opens an edit form and presses Save without changing anything would be told that the record was not found. The cure is to test for failure with mysqli_errno(), or to connect with the MYSQLI_CLIENT_FOUND_ROWS flag, which makes MySQL report matched rows instead.

    Exercise 4.32. Rewrite the vulnerable login from Listing 4.18 using a prepared statement and password_hash() / password_verify(), and explain why storing plain passwords is worse than the injection hole.

    Answer

    When the account is created, store only the hash:

    $hash = password_hash($password, PASSWORD_DEFAULT);
$stmt = mysqli_prepare($conn, "INSERT INTO users (username, password) VALUES (?, ?)");
mysqli_stmt_bind_param($stmt, "ss", $username, $hash);
mysqli_stmt_execute($stmt);

    $stmt = mysqli_prepare($conn, "SELECT password FROM users WHERE username = ?");

} else {

}

    The injection hole is a flaw in one query, and fixing that query closes it. Plain-text passwords are a flaw in the data itself: anyone who ever obtains a copy of the table, through a backup, a leaked file or a different injection, reads every user's password at once, and because people reuse passwords, the damage spreads to their accounts on other sites. A hash cannot be reversed, so the same leak gives the attacker far less.

    Exercise 4.37. (2 marks) What is a primary key? How does it differ from a foreign key?

    Answer

    A primary key is the column that identifies a row uniquely: never repeated, never null, one per table. A foreign key is a column holding the primary key of another table, which is what makes a join possible and what keeps the two tables consistent.

    roll   INT PRIMARY KEY                       -- in students
course VARCHAR(10), FOREIGN KEY (course) REFERENCES courses(code)

    Exercise 4.38. (2 marks) What is the difference between WHERE and HAVING?

    Answer

    WHERE filters rows before grouping; HAVING filters groups after. That is why an aggregate cannot appear in a WHERE clause — at that point no group exists yet.

    SELECT course, COUNT(*) FROM students
WHERE  marks >= 40        -- rows first
GROUP BY course
HAVING COUNT(*) > 5;      -- then groups

    Exercise 4.40. (5 marks) What is SQL injection? Explain with an example and give the remedy.

    Answer

    What it is. When a query is built by pasting user input into a string, the input becomes part of the program rather than staying data, and the user can change what the query does.

    Example. A login built like this:

    $sql = "SELECT * FROM users WHERE username = '$user' AND password = '$pass'";

    If the visitor types anything' OR '1'='1 as the password, the query that actually runs is:

    SELECT * FROM users WHERE username = 'admin' AND password = 'anything' OR '1'='1'

    '1'='1' is always true, so a row is returned and the login succeeds with the wrong password.

    The remedy — a prepared statement. The query and the data travel separately, so the data can never be parsed as SQL:

    $sql  = "SELECT * FROM users WHERE username = ? AND password = ?";
$stmt = mysqli_prepare($conn, $sql);
mysqli_stmt_bind_param($stmt, "ss", $user, $pass);
mysqli_stmt_execute($stmt);
$result = mysqli_stmt_get_result($stmt);

    Two more points: mysqli_real_escape_string() also works but must be applied to every value without exception, so it is easier to get wrong; and a placeholder can stand for a value only — a table or column name must be checked against a whitelist instead.

    Unit 4 demonstrates the attack and the fix, live.

    Exercise 4.41. (5 marks) Explain JOIN with an example. Differentiate INNER JOIN and LEFT JOIN.

    Answer

    A join combines rows from two tables using a column they share — a foreign key and the primary key it points at.

    SELECT s.name, c.title
FROM students s
INNER JOIN courses c ON s.course = c.code;
    INNER JOIN LEFT JOIN
    Keeps only rows that match in both tables every row of the left table, matched or not
    Unmatched rows dropped kept, with NULL in the right-hand columns
    Use for "students with their course" "every course and how many students, including those with none"

    A worked contrast: a course with no students appears in a LEFT JOIN with a null count and vanishes entirely from an INNER JOIN. Note also that COUNT(*) would count the unmatched row as 1, so the correct form is COUNT(s.roll).

    Exercise 4.42. (10 marks) Write a PHP program to connect to MySQL, create a table, insert records and display them in an HTML table.

    Answer

    1. The SQL, run once in phpMyAdmin:

    CREATE DATABASE IF NOT EXISTS college;
USE college;

CREATE TABLE students (
    roll   INT         PRIMARY KEY,
    name   VARCHAR(50) NOT NULL,
    course VARCHAR(10),
    marks  INT DEFAULT 0
);

    2. Connect — in its own file, so the password appears once:

    <?php  // db.php
$conn = mysqli_connect("localhost", "root", "", "college");
if (!$conn) die("Connection failed: " . mysqli_connect_error());

    3. Insert, with a prepared statement:

    <?php
require "db.php";

$sql  = "INSERT INTO students (roll, name, course, marks) VALUES (?, ?, ?, ?)";
$stmt = mysqli_prepare($conn, $sql);
mysqli_stmt_bind_param($stmt, "issi", $roll, $name, $course, $marks);

$roll = 2231045; $name = "Zoya Khan"; $course = "BSCCS"; $marks = 82;

if (mysqli_stmt_execute($stmt)) {
    echo "The record is added in the database!";
} else {
    echo "Error: " . mysqli_error($conn);
}

    4. Retrieve and display:

    <?php
$result = mysqli_query($conn, "SELECT roll, name, course, marks
                               FROM students ORDER BY marks DESC");
if (!$result) die("Query failed: " . mysqli_error($conn));
?>

<table border="1">
  <tr><th>Roll</th><th>Name</th><th>Course</th><th>Marks</th></tr>
  <?php while ($row = mysqli_fetch_assoc($result)): ?>
    <tr>
      <td><?= (int) $row["roll"] ?></td>
      <td><?= htmlspecialchars($row["name"]) ?></td>
      <td><?= htmlspecialchars($row["course"]) ?></td>
      <td><?= (int) $row["marks"] ?></td>
    </tr>
  <?php endwhile; ?>
</table>

<p><?= mysqli_num_rows($result) ?> students.</p>

    The marks are in the details: checking the return value of every query, using a prepared statement, escaping every value on the way out, and the while ($row = mysqli_fetch_assoc($result)) loop — which works because each call returns the next row and finally null.
