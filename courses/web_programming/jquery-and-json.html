    Unit 5: jQuery and JSON¶

    Everything so far ran on the server, and every interaction cost the visitor a whole new page. This unit moves to the browser. It introduces jQuery, the library that makes JavaScript's handling of the page short and uniform, and then uses it for AJAX: asking the server for a small piece of data in the background and changing part of the page without a reload. JSON, the format in which that data travels, is the thread that ties the browser and the PHP of the earlier units together.

    It corresponds to Unit 5 of the course, jQuery and JSON, which is allotted 6 lecture hours. The PHP endpoints in the examples are written in the style of Units 3 and 4, so the unit is also a review of them.

    Learning outcomes

    • Include jQuery correctly and explain what $(document).ready() is for.
    • Select elements by tag, id, class, attribute and relationship, and change their text, HTML, value, attributes and styling.
    • Attach event handlers with .on(), use $(this), and explain why delegation is needed for elements that did not exist when the page loaded.
    • Read and write JSON, and say exactly how a PHP array becomes a JSON array or a JSON object.
    • Fetch data from a PHP script with $.get, $.post, $.getJSON and $.ajax, and handle the failure case.
    • Build a PHP endpoint that returns JSON, with the right content type.

    5.1 Why the browser needs a library of its own¶

    The idea, first

    Units 1 to 4 all lived on the server. Every interaction cost a whole page: click, request, wait, the screen goes white, a new page arrives. That is a perfectly good way to build a site, and for a form it is often the right one. But some things are absurd done that way — a "check if this username is free" that reloads the page, a table you cannot sort without a round trip, a search that clears itself every time you type.

    AJAX is the fix: JavaScript asks the server for a small piece of data in the background and updates part of the page. The user sees no reload. JSON is the format that data almost always arrives in. And jQuery is a library that makes both the DOM work and the AJAX call short enough to write in a lecture.

    One honest note. jQuery was written in 2006 to paper over browsers that disagreed with each other, and modern JavaScript has absorbed most of what made it essential — document.querySelectorAll and fetch() do the two main jobs. It is on your course outline, it is still on a very large share of the web, and it is a genuinely good way to learn what the DOM even is. Learn it, and know that fetch() is what you would reach for in new code.

    5.2 Getting jQuery onto the page¶

    Way Code When
    From a CDN <script src="https://code.jquery.com/jquery-3.7.1.min.js"></script> Quickest; needs the internet
    A local copy <script src="js/jquery-3.7.1.min.js"></script> Do this for your practical file. The lab machine may have no internet, and your project must still run

    Order matters

    The <script> that loads jQuery must come before any script that uses $. Put jQuery last in <head>, or — better — put both scripts just before </body>. "$ is not defined" in the console always means this.

    $(document).ready()¶

    A script in <head> runs before the body exists, so $("#result") finds nothing and your code silently does nothing. Wrapping it in ready defers it until the DOM is built.

    the three forms

    // full form
$(document).ready(function () {
    // your code
});

// shorthand — identical, and what most code uses
$(function () {
    // your code
});

// and if the script tag is at the end of <body>, none of this is needed
// at all, because the DOM above it already exists.

    Not the same as window.onload, which also waits for every image to finish loading. ready fires as soon as the HTML is parsed.

    5.3 Selectors¶

    $(...) takes a CSS selector and returns a jQuery object holding every match — zero, one or many. Every method you then call applies to all of them, which is why jQuery code has so few loops in it.

    Selector Matches
    $("p") every <p>
    $("#total") the element with id="total" — at most one
    $(".error") every element with class="error"
    $("input[type='checkbox']") by attribute
    $("ul li") every li anywhere inside a ul
    $("ul > li") only direct children
    $("tr:even"), :odd alternate rows — zero-based
    $("li:first"), :last the first / last match
    $("input:checked") ticked boxes and chosen radios
    $("p:contains('Delhi')") by text content
    $(this) inside a handler: the element the event happened on
    $("#a, #b, .c") several selectors at once

    5.4 Changing the page¶

    Method Does Note
    .text() get or set the text escapes markup — use this for anything a user typed
    .html() get or set the inner HTML renders tags; an XSS hole if the content came from a user
    .val() get or set a form field's value the one for input, select, textarea
    .attr("href") get or set an attribute
    .prop("checked") get or set a live property use for checked, disabled, selected
    .css("color", "red") set a style fine for one property; a class is better for many
    .addClass / .removeClass / .toggleClass change classes the tidy way to restyle
    .append / .prepend add inside, at the end / start
    .after / .before add outside
    .remove() / .empty() delete the element / its contents
    .each(fn) loop over the matches $(this) is the current one
    .show() / .hide() / .toggle() visibility add a duration for a fade
    .fadeIn / .slideUp / .animate effects chainable and queued

    Chaining

    Every method that changes something returns the same jQuery object, so calls can be strung together: $("#msg").text("Saved").css("color", "green").fadeIn(300);. That is why jQuery code reads as one sentence per line.

    Each button applies one DOM method to the box. .text() shows the typed string as characters, so the tags are visible, whereas .html() parses it as markup and the word becomes bold: the same string, two very different results. .append() adds a paragraph, .toggleClass() adds or removes the class fancy, .attr() sets a title attribute, .fadeToggle() animates the paragraph away and back, .empty() removes the children of the box, and the last button restores the original.

    .html() with user input is the same hole as echo $_POST

    $("#out").html(userText) renders whatever tags are in it, in the visitor's browser. Unit 3 taught htmlspecialchars() for the server side; on the client side the equivalent is simply to use .text(). Reach for .html() only when you built the string.

    5.5 Events¶

    Written as Fires when
    $(sel).on("click", fn) the modern, general form — use this
    $(sel).click(fn) a shorthand for the same thing
    "submit" a form is submitted — on the <form>, not the button
    "change" a select, checkbox or radio changes
    "input", "keyup" the user types
    "focus", "blur" a field is entered / left
    "mouseenter", "mouseleave" hover
    "dblclick" double click

    Inside a handler, this is the plain DOM element and $(this) wraps it so jQuery methods work. e.preventDefault() stops the default behaviour — the form submitting, the link navigating.

    Listing 5.4. Events, including delegation

    HTML

    <p>
  <button id="add">Add a row</button>
  <label style="margin-left:12px">
    <input type="checkbox" id="use-delegation" checked> use delegation
  </label>
</p>

<ul id="list">
  <li>Original row <button class="del">delete</button></li>
</ul>

<p>
  <label>Live search: <input id="q" placeholder="type to filter"></label>
</p>

<p id="log" style="font-family:monospace;font-size:13px;color:#12808f"></p>

    JavaScript

    $(function () {

    var n = 1;

    // ---- delegated: the handler lives on #list, which always exists -----
    $("#list").on("click", ".del", function () {
        if (!$("#use-delegation").prop("checked")) return;
        $(this).closest("li").remove();
        log("deleted by the DELEGATED handler");
    });

    // ---- direct: bound only to the buttons that existed just now -------
    $(".del").on("click", function () {
        if ($("#use-delegation").prop("checked")) return;
        $(this).closest("li").remove();
        log("deleted by the DIRECT handler");
    });

    $("#add").on("click", function () {
        n++;
        $("#list").append("<li>Row " + n + " <button class='del'>delete</button></li>");
        log("added row " + n + " — try deleting it with each setting");
    });

    // ---- typing ---------------------------------------------------------
    $("#q").on("input", function () {
        var term = $(this).val().toLowerCase();
        $("#list li").each(function () {
            var match = $(this).text().toLowerCase().indexOf(term) > -1;
            $(this).toggle(match);
        });
        log("filtering on: " + (term || "(nothing)"));
    });

    function log(m) { $("#log").text(m); }
});

    Adding a row and then deleting the new row shows the difference between the two kinds of handler. With delegation, the handler lives on the list, which always exists, so it works on rows added later. Without it, the handler was bound only to the buttons that existed when the page loaded, so the new row's button does nothing. This is the single most common jQuery bug. The search box filters the list as the user types.

    Why delegation is needed

    $(".del").on("click", …) finds the buttons that exist at that moment and attaches a handler to each. A button created later never had one attached. $("#list").on("click", ".del", …) attaches one handler to the list, which checks on each click whether what was clicked matches .del — so it works for rows added at any time. Any list you build from AJAX data needs this.

    HTML

    <form id="reg">

    CSS

    JavaScript

    $(function () {

    $("#reg").on("submit", function (e) {
        e.preventDefault();            // stop the page reloading
        $(".err").text("");
        $("input").removeClass("bad");
        $("#ok").text("");

        var ok = true;

        var name = $.trim($("#sname").val());
        if (name.length < 3) {
            fail("#sname", "at least 3 characters");
            ok = false;
        }

        var email = $.trim($("#email").val());
        if (!/^[^\s@]+@[^\s@]+\.[a-z]{2,}$/i.test(email)) {
            fail("#email", "not a valid address");
            ok = false;
        }

        var marks = $("#marks").val();
        if (marks === "" || isNaN(marks) || marks < 0 || marks > 100) {
            fail("#marks", "a number from 0 to 100");
            ok = false;
        }

        if (ok) {
            $("#ok").text("All good — this is where the AJAX call would go.");
        }
    });

    function fail(sel, msg) {
        $(sel).addClass("bad");
        $("#e-" + sel.substring(1)).text(msg);
    }
});

    Submitting the form empty, or with a bad email address, shows a message beside each faulty field without the page reloading, because e.preventDefault() cancels the browser's own submission. A valid submission shows "All good — this is where the AJAX call would go." Remember Unit 3: this is a convenience, and the server must still check.

    5.6 JSON¶

    JavaScript Object Notation: a text format for structured data. It looks like a JavaScript literal, every language can read it, and it is what a PHP script sends when it is answering a program rather than a person.

    JSON type Written Rules
    object {"name": "Zoya", "marks": 82} keys are always double-quoted strings
    array [1, 2, 3] ordered, mixed types allowed
    string "Delhi" double quotes only — never single
    number 82, -1.5 no leading +, no hex
    boolean true, false lower case
    null null lower case

    Four things JSON does not allow

    Comments. A trailing comma after the last item. Single quotes. Unquoted keys. All four are legal in JavaScript and all four make json_decode() return null — which is the usual reason an AJAX call "returns nothing".

    PHP arrays and JSON¶

    Listing 5.6. json_encode: array or object?

    <?php

    "updated"  => null,

    Listing 5.7. json_decode: array or object?

    <?php
$json = '{"name":"Riya","marks":91,"subjects":["PHP","MySQL"],"active":true}';

echo "\n", json_encode(json_decode($json, true)), "\n";

    5.7 AJAX¶

    Asynchronous JavaScript And XML — a name from 2005, when the format was XML. Nobody uses XML for it now; the idea survived and the name stuck.

    Call Does
    $.get(url, data, success) a GET; the response is text or HTML
    $.post(url, data, success) a POST
    $.getJSON(url, data, success) a GET whose response is parsed as JSON before your function sees it
    $.ajax({...}) all of the above, with every option exposed — the one to use when you need error handling
    $("#x").load(url) fetch HTML and drop it straight into an element

    Where to look when an AJAX call misbehaves

    Each example below comes with the .php file that answers it. When you try an AJAX call on your own machine, open the Network tab of the browser's developer tools: it logs every request and its response, and it is where the fault will show.

    Listing 5.8. $.get — the simplest AJAX call

    HTML

    <p><button id="go">Ask the server for the time</button></p>
<p id="out" style="font-family:monospace">nothing yet</p>

    JavaScript

    $(function () {
    $("#go").on("click", function () {
        $("#out").text("loading…");

        $.get("time.php", function (response) {
            $("#out").text(response);
        });
    });
});

    time.php

    <?php
echo "The server says it is " . date("H:i:s") . " and there are "
   . rand(3, 9) . " people online.";

    The file time.php is the server side of this example. Requested on its own, it replies with plain text (the time and the count vary from request to request):

    The reply:

    The server says it is 09:41:07 and there are 3 people online.

    Pressing the button shows "loading…" and then the server's reply in the paragraph. The page never reloads; only the paragraph changes. The file time.php is the server side.

    What jQuery is doing for you¶

    AJAX is not a jQuery feature. The browser has always had an object for it, and modern JavaScript has a much nicer one. Knowing all three matters: an examiner asks "what does AJAX stand for and which object performs it", and a real project written today would use the third.

    the same request, three ways

    // 1. XMLHttpRequest — the original object, from 1999. This is what
//    "AJAX" literally means, and what jQuery wraps.
var xhr = new XMLHttpRequest();
xhr.open("GET", "students.php?course=BSCCS");
xhr.onreadystatechange = function () {
    // readyState 4 = done;  status 200 = OK
    if (xhr.readyState === 4 && xhr.status === 200) {
        var data = JSON.parse(xhr.responseText);   // you parse it yourself
        console.log(data.count);
    }
};
xhr.send();

// 2. jQuery — the same thing, with the parsing and the branching done for you
$.getJSON("students.php", { course: "BSCCS" }, function (data) {
    console.log(data.count);
});

// 3. fetch() — built into every browser since 2017, and what you would
//    write in new code today
fetch("students.php?course=BSCCS")
    .then(function (response) {
        if (!response.ok) throw new Error("HTTP " + response.status);
        return response.json();
    })
    .then(function (data) { console.log(data.count); })
    .catch(function (err) { console.error(err); });

// the same, with async/await
async function load() {
    var response = await fetch("students.php?course=BSCCS");
    var data = await response.json();
    console.log(data.count);
}

    Nine lines, four lines, five lines. jQuery's advantage in 2006 was that XMLHttpRequest worked differently in every browser; that problem is long gone, which is why fetch exists.

    Term Means
    AJAX Asynchronous JavaScript And XML — a technique, not a library. The XML part is historical; JSON replaced it
    Asynchronous the script does not stop and wait. It hands over a function to call when the reply arrives, and carries on
    readyState 0 unsent, 1 opened, 2 headers received, 3 loading, 4 done
    status the HTTP code: 200 OK, 404 not found, 500 server error
    responseText the reply as a string — you call JSON.parse on it yourself

    Why 'asynchronous' is the important word

    The request may take half a second. If the browser waited, the whole tab would freeze — no scrolling, no typing, nothing. So the call returns immediately and your callback runs later. That is also why you cannot write var data = $.getJSON(...); use(data); — at the next line the reply has not arrived. Everything that depends on the answer goes inside the callback.

    5.8 Solved problems¶

    Example 5.1: 'My jQuery does nothing at all'

    Problem. A page has jQuery included and a click handler that never fires. No error is visible. Work through the causes in order.

    Step 1 — open the console

    F12, Console tab. "No error is visible" almost always means nobody looked. $ is not defined means jQuery did not load, or loaded after your script.

    Step 2 — did the selector match anything?

    console.log($("#go").length). Zero means the selector is wrong or the element does not exist yet. Note that jQuery does not complain about a selector that matches nothing — it returns an empty collection and every method on it succeeds silently. That is the single biggest difference from plain JavaScript, where document.getElementById("go").onclick = … throws.

    Step 3 — is the code running too early?

    If the script is in <head> without $(function () { … }), the body does not exist when it runs. Wrap it, or move the script to the end of the body.

    Step 4 — was the element created later?

    If the button came from an AJAX response or an .append(), a direct handler was never attached to it. Use delegation: $(document).on("click", "#go", …).

    Answer. Console → selector length → ready wrapper → delegation. In that order.

    Example 5.2: The AJAX call returns nothing

    Problem. $.getJSON("data.php", function (d) { console.log(d); }) logs nothing at all, and the network tab shows a 200. Explain.

    Step 1 — 200 means PHP answered

    The request succeeded. So the problem is the content of the reply, and $.getJSON silently skips its success callback when the body will not parse as JSON.

    Step 2 — look at the raw response

    Open data.php directly in the browser. Nine times out of ten there is a PHP warning printed before the JSON — "Undefined array key", a print_r left in from debugging, or whitespace before <?php. A single stray character makes the whole body invalid.

    Step 3 — add an error handler and see the message

    $.getJSON(…).fail(function (xhr, status, err) { console.log(status, err, xhr.responseText); }). status will read "parsererror" and responseText shows the offending body.

    Step 4 — prevent it happening again

    Send header("Content-Type: application/json"); as the very first thing, never echo anything but the encoded JSON, and leave off the closing ?> so no trailing newline can escape.

    Answer. parsererror — the reply was not valid JSON, usually because a warning was printed before it

    Example 5.3: Why the results arrive in the wrong order

    Problem. A live-search box sends a request per keystroke. Typing "riya" quickly sometimes leaves the results for "ri" on screen. Explain and fix.

    Step 1 — asynchronous means unordered

    Four requests go out. Nothing guarantees the replies come back in the same order: if the reply for "ri" is slow and arrives after the reply for "riya", it overwrites the newer results. This is a genuine race, not a bug in your code.

    Step 2 — the cheap fix: debounce

    Wait until the typing pauses. clearTimeout then setTimeout(…, 250) means one request instead of four, which removes the race in practice and is kinder to the server. This is what the live-search lab above does.

    Step 3 — the complete fix: cancel or stamp

    Keep the jqXHR object and call .abort() on the previous one before sending a new one. Or send a sequence number with each request and ignore a reply whose number is not the latest.

    Step 4 — what not to do

    Do not set async: false. It freezes the whole browser tab until the reply arrives, and it is deprecated for exactly that reason.

    Answer. Debounce the typing; abort the previous request or check a sequence number

    Example 5.4: Which is safe: .text() or .html()?

    Problem. A search result includes a student called <img src=x onerror=alert(1)>, because someone registered with that name. What happens in each of the two lab versions, and what should the code be?

    Step 1 — where the danger is

    The name is stored fine — Unit 4's prepared statement saw it as data. The danger is on the way out, and it now has two exits: the PHP page and the JSON that JavaScript inserts.

    Step 2 — .html() renders it

    Building html += "" + s.name + "" and calling .html() puts the tag into the page, and the browser runs the onerror. Exactly the Unit 3 hole, in a new place.

    Step 3 — .text() does not

    Building the element and setting its text keeps the name as characters: $("<div>").text(s.name). jQuery escapes it for you.

    Step 4 — the pattern to use

    Build with $("<tag>") and .text(), then .append() it. It is three lines instead of one and it cannot be exploited.

    Answer. Use .text() for any value that came from a user or a database

    5.9 Common mistakes to avoid¶

    • Do not load your script before jQuery. "$ is not defined" means exactly that.
    • Do not run DOM code outside $(function () { … }) when the script is in <head>.
    • Do not attach handlers directly to elements that do not exist yet. Delegate.
    • Do not use .text() on an input or .val() on a div.
    • Do not build HTML by concatenating user data and passing it to .html(). Use .text().
    • Do not forget e.preventDefault() in a submit handler — the page will reload and it will look as though nothing happened.
    • Do not write comments, single quotes, unquoted keys or trailing commas in JSON.
    • Do not echo anything from an endpoint except the JSON — no debugging print_r, no stray whitespace.
    • Do not omit header("Content-Type: application/json");, and do not put it after an echo.
    • Do not leave an AJAX call without an error handler.
    • Do not skip the debounce on a search-as-you-type box: one request per keystroke is wasteful and the replies can overtake one another.
    • Do not expect the server to have validated anything just because the JavaScript did. An AJAX request is an ordinary HTTP request and can be sent by anything.

    Exercise 5.17. Which line stops a form from reloading the page when it is submitted?

    • (b) return true;
    • (c) $("form").hide();
    • (d) Removing the action attribute
    Answer

    The answer is (a).

    • (b) Returning true allows the default; returning false would cancel it, but preventDefault is the explicit form.

    • (d) With no action the form posts to the same page, which is still a reload.

    Exercise 5.18. You are inserting a student's name from an AJAX response into the page. Which is right?

    • (a) $("<div>").text(s.name).appendTo("#out")
    • (b) $("#out").html("<div>" + s.name + "</div>")
    • (c) $("#out").append(s.name)
    • (d) document.write(s.name)
    Answer

    The answer is (a).

    Exercise 5.21. Build a table where clicking a column heading sorts the rows, using only jQuery, with no request to the server.

    Answer 
    $(function () {
    $("#t th").on("click", function () {
        var col = $(this).index();                 // which column was clicked
        var asc = !$(this).data("asc");            // flip the direction each time
        $(this).data("asc", asc);

        var rows = $("#t tr:gt(0)").get();         // every row except the header
        rows.sort(function (a, b) {
            var x = $(a).children().eq(col).text();
            var y = $(b).children().eq(col).text();
            var nx = parseFloat(x), ny = parseFloat(y);
            var r = (!isNaN(nx) && !isNaN(ny)) ? nx - ny : x.localeCompare(y);
            return asc ? r : -r;
        });
        $("#t").append(rows);                      // appending moves the existing rows
    });
});

    The rows are collected into an ordinary array, sorted with a comparison function that compares numbers as numbers and everything else as text, and then appended back in the new order. Appending an element that is already in the page moves it rather than copying it.

    Exercise 5.25. Explain, in three sentences, why $.getJSON needs no JSON.parse while $.get may.

    Answer

    $.getJSON(url, data, callback) is shorthand for $.ajax with dataType: "json", so jQuery parses the response body itself and passes your function a ready-made JavaScript object. $.get hands over the response as it arrives: with no dataType, jQuery guesses from the Content-Type header, so a reply that is not declared as JSON reaches the callback as a string that needs JSON.parse. The practical rule is to send Content-Type: application/json from the endpoint and to use $.getJSON, so that the intention is explicit and does not depend on a guess.

    Exercise 5.26. Convert the live search from $.getJSON to fetch() with async/await, and say which you find clearer.

    Answer 
    async function search(term) {
    const response = await fetch("search.php?q=" + encodeURIComponent(term));
    if (!response.ok) {
        throw new Error("The server answered " + response.status);
    }
    const data = await response.json();

    const html = data.map(s =>
        "<div><b>" + s.name + "</b> \u2014 " + s.course + ", " + s.marks + " marks, " + s.city + "</div>"
    ).join("");
    $("#results").html(html);
}

    Most people find the async/await form clearer, because the steps read from top to bottom like synchronous code and there is no nesting of callbacks. It asks for more care in two places, however: fetch does not treat a 404 or 500 reply as a failure, so response.ok must be tested by hand, and the query string must be encoded by hand with encodeURIComponent, where $.getJSON does both for you. (The string-building in this version has the same weakness that the previous exercise removed.)

    Exercise 5.27. A page loads 500 rows and filters them in the browser as the user types. A second page asks the server on each keystroke. When is each the better design?

    Answer

    Filtering in the browser is better when the whole set is small enough to send once (500 rows is) and is not secret. Each keystroke is answered instantly, with no network delay and no load on the server, and it keeps working if the connection drops. Its costs are the initial transfer and memory, and the fact that every row, including any the user was not supposed to see, has been sent to the browser.

    Asking the server on each keystroke is better when the set is large (thousands of rows or more), when it changes while the user is typing, or when access rules mean that the user may see only some of it, because the server decides what to send. It costs a request per keystroke, which is why the typing should be debounced, and it feels slower on a poor connection.

    Exercise 5.28. (2 marks) What is jQuery? Write the syntax to include it.

    Answer

    Exercise 5.29. (2 marks) What is $(document).ready() and why is it needed?

    Answer

    It defers your code until the HTML has been parsed, so every element exists before a selector looks for it. A script in <head> runs before the body exists, so $("#result") would match nothing and — because jQuery fails silently on an empty selection — nothing would happen and no error would appear.

    $(document).ready(function () { … });
$(function () { … });          // the shorthand, identical

    Unlike window.onload, it does not wait for images to finish loading.

    Exercise 5.30. (2 marks) What is JSON? Give an example.

    Answer

    JavaScript Object Notation — a lightweight, language-independent text format for structured data, and what a server sends when it is answering a program rather than a person.

    {"roll": 2231045, "name": "Zoya", "subjects": ["PHP", "MySQL"], "active": true}

    Rules that catch people out: keys and strings must use double quotes, and there may be no comments and no trailing comma — all three are legal in JavaScript and invalid in JSON.

    Exercise 5.31. (2 marks) Differentiate json_encode() and json_decode().

    Answer
    • json_encode($value) — PHP value → JSON string. A PHP array with gapless integer keys becomes a JSON array; anything else becomes a JSON object.
    • json_decode($string) — JSON string → PHP. By default it produces objects (read with ->); pass true as the second argument for associative arrays (read with []).
    echo json_encode(["name" => "Zoya"]);   // {"name":"Zoya"}
$d = json_decode('{"name":"Zoya"}', true);
echo $d["name"];                        // Zoya

    Exercise 5.32. (2 marks) What is AJAX? What does the acronym stand for?

    Answer

    Asynchronous JavaScript And XML — a technique, not a library, in which JavaScript requests data from the server in the background and updates part of the page without reloading it. The XML in the name is historical; JSON is what is actually used.

    The underlying object is XMLHttpRequest; jQuery wraps it as $.get, $.post, $.getJSON and $.ajax, and modern JavaScript offers fetch().

    Exercise 5.33. (2 marks) Difference between .text() and .html() in jQuery.

    Answer

    .text() sets or reads the element's text, escaping any markup so tags are shown as characters. .html() sets or reads the inner HTML, so tags take effect.

    $("#p").text("<b>hi</b>");   // shows:  <b>hi</b>
$("#p").html("<b>hi</b>");   // shows:  hi   in bold

    Use .text() for anything that came from a user or a database; .html() only for markup you built yourself, or you have an XSS hole.

    Five- and ten-mark questions¶

    Exercise 5.34. (5 marks) Explain jQuery selectors with examples.

    Answer

    A selector is passed to $() and returns a jQuery object holding every matching element — zero, one or many — which is why jQuery code needs so few loops. A selector matching nothing is not an error; it returns an empty collection and every method on it silently succeeds.

    Selector Matches
    $("p") every <p> — by element name
    $("#total") the element with id="total"
    $(".error") every element with class="error"
    $("[data-role='box']") by attribute
    $("ul li") / $("ul > li") descendant / direct child
    $("tr:even"), $("li:first"), $("input:checked") by position or state
    $(this) inside a handler, the element the event happened on 
    $(".info").css("color", "red");        // all of them at once
console.log($(".info").length);        // how many matched

    Exercise 5.35. (5 marks) What is event delegation in jQuery, and why is it needed?

    Answer

    $(".del").on("click", fn) attaches a handler to the elements that exist at that moment. An element created later — by .append() or from an AJAX response — never had one attached, so it does not respond.

    Delegation attaches one handler to a container that does exist, and the container checks on each click whether what was clicked matches the selector:

    // direct — only works for rows present when this line ran
$(".del").on("click", function () { $(this).closest("li").remove(); });

// delegated — works for rows added at any time
$("#list").on("click", ".del", function () { $(this).closest("li").remove(); });

    It works because a click bubbles up from the element to its ancestors. Any list built from AJAX data needs this, and it is also more efficient: one handler instead of one per row.

    Exercise 5.36. (10 marks) Explain AJAX. Write a program in which a jQuery page fetches data from a PHP script as JSON and displays it without reloading.

    Answer

    What AJAX is. Asynchronous JavaScript And XML: JavaScript makes an HTTP request in the background, the server replies with a small piece of data (almost always JSON), and a callback updates part of the page. The user sees no reload. "Asynchronous" means the script does not wait — which is why everything that depends on the answer must go inside the callback.

    The server side — students.php, which answers a program, so it sends JSON rather than HTML:

    <?php
header("Content-Type: application/json");

$conn = mysqli_connect("localhost", "root", "", "college");

$course = $_GET["course"] ?? "";
$stmt = mysqli_prepare($conn,
    "SELECT roll, name, marks FROM students WHERE course = ? ORDER BY marks DESC");
mysqli_stmt_bind_param($stmt, "s", $course);
mysqli_stmt_execute($stmt);
$result = mysqli_stmt_get_result($stmt);

$rows = [];
while ($row = mysqli_fetch_assoc($result)) {
    $row["marks"] = (int) $row["marks"];      // so JavaScript gets a number
    $rows[] = $row;
}

echo json_encode(["ok" => true, "count" => count($rows), "students" => $rows]);

    The client side:

    <select id="course"><option>BSCCS</option><option>BAECO</option></select>
<button id="load">Load</button>
<table id="out"></table>

<script>
$(function () {
    $("#load").on("click", function () {

        $.getJSON("students.php", { course: $("#course").val() })
            .done(function (data) {
                var rows = "<tr><th>Roll</th><th>Name</th><th>Marks</th></tr>";
                $.each(data.students, function (i, s) {
                    rows += "<tr><td>" + s.roll + "</td><td>" +
                            s.name + "</td><td>" + s.marks + "</td></tr>";
                });
                $("#out").html(rows);
            })
            .fail(function (xhr) {
                alert("Request failed: " + xhr.status);
            });
    });
});
</script>

    Points that carry marks: the endpoint sends Content-Type: application/json before any output; $.getJSON parses the reply for you, so no JSON.parse is needed; the failure case is handled; and the values are cast to integers on the server so JavaScript receives numbers rather than strings.
