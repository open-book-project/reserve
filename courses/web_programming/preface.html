    Preface¶

    Who this book is for¶

    This book is a complete treatment of an advanced university course in web programming. It is written for a student who knows HTML and CSS, which is the prerequisite of the course, and who wants to learn to build interactive, data-driven websites: pages that react to what a visitor types, remember things, and talk to a database.

    The course is worth four credits, three of lecture and one of practical, and its eligibility condition is a pass in Class XII. This book covers the lecture part, forty-five hours of it; it does not contain a laboratory manual. Its worked examples and exercises nevertheless include the programs that a practical examination typically asks for, such as a form that adds two numbers, a registration form, a login with a session, and the four operations on a database table.

    By the end of the course, in the words of the course outline, a student should be able to:

    • develop interactive and dynamic websites;
    • write programs to communicate with the server using the GET and POST methods;
    • learn to connect to and manipulate databases using MySQL;
    • validate server-side (back-end) data.

    How the book follows the course¶

    The five units of the book follow the five units of the course in order, and each unit assumes the one before it. The hours are those of the course scheme.

    Course unit Hours Course text Covered in
    1 7 Introduction to PHP: basic syntax, defining variables and constants, data types including arrays, operators and expressions, decision making statements, constructs for iterations Unit 1, Introduction to PHP
    2 5 String Handling: creating a string and accessing its content, searching and replacing content of a string, and other built-in functions Unit 2, String Handling
    3 12 Handling HTML Form with PHP: creating a form, submitting data to the server at the backend using GET and POST methods, GET vs POST methods, PHP global functions Unit 3, Handling HTML Forms with PHP
    4 15 Database: connectivity with MySQL: connectivity with database, database creation, creating tables, create, retrieve, update, and delete (CRUD) operations Unit 4, Database: MySQL Connectivity
    5 6 jQuery and JSON: introduction to jQuery syntax (selectors, events, AJAX, JSON) Unit 5, jQuery and JSON

    Functions and the splitting of a program across files are not named in the course outline, but every later unit uses them, so Unit 1 teaches them. Regular expressions and the escaping of output, likewise, are treated in Unit 2 because the form validation of Unit 3 needs them.

    How to use this book¶

    Install the real thing first. Section 1.2 walks through installing XAMPP, which bundles the Apache web server, the MySQL database and PHP. Your practical file and your examination expect these on your own machine, and a page of PHP cannot be tried by opening the file in a browser: it has to be requested from the server through an address that begins http://localhost/.

    Type the listings. Each unit contains numbered listings (Listing 1.1, 1.2, and so on) that are complete programs. Each is followed by the output it produces, so you can check your own result against it. Where a program takes input from a form or from the address, the book shows the request and the reply. Change a value, predict the new output, and then run it; this is the quickest way to learn a language in which so many surprises hide in small rules. Details that depend on the version of PHP (the wording of a warning, for example) can differ a little on your installation.

    Read the boxes. Notes give definitions and asides, tips name the idea to take away, and warnings mark the mistakes that cost students marks and, in real applications, cost users their data.

    Work the exercises. Every unit ends with a Summary and an Exercises section. The exercises include short questions with reasons given for every option, programs to predict, blanks to fill, lines to put in order and programs to write, followed by practice problems and by questions in the shape of the examination paper. Each exercise has its answer folded below it. Attempt it on paper first: reading a model answer and nodding at it produces a feeling of understanding that does not survive the examination hall, whereas writing an answer and then comparing it does.

    The back of the book has two further parts: a Reference (error messages and what they mean, syntax and function summaries, a security checklist), and a Glossary and Further Reading.

    Answering examination questions¶

    The questions in the exercises are grouped by unit and by size, because the size tells you what the examiner wants.

    • A two-mark question wants a definition and, ideally, one concrete example, not a paragraph.
    • A five-mark question wants structure: a table for a "difference between", or three or four labelled points.
    • A ten-mark question wants an answer with parts: explain, then illustrate with code, then say when it fails.

    Four habits earn marks in all of them.

    Always name the function

    "We can validate the email" earns less than "we call filter_var($e, FILTER_VALIDATE_EMAIL), which returns the address or false".

    Always give an example

    Two lines of code in a two-mark answer is usually the difference between full marks and half.

    Use a table for comparisons

    A "difference between" answer in a table with three or four rows is faster to write and faster to mark.

    Say what breaks

    Naming the failure ("without enctype, $_FILES is empty") shows understanding rather than memory.

    The split of marks between internal assessment, the end-semester theory paper and the practical examination is set by the institution and changes from year to year, so check the current scheme with your teacher. What does not change is the shape of the questions.
