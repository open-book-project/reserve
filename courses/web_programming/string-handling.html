    Unit 2: String Handling¶

    A web application is, to a large extent, a machine for handling text: every form field arrives as text, every page leaves as text. This unit is about the strings in which that text lives: how to write them, how to reach into them, how to search them and change them, how to format them for people, and how to make a string typed by a visitor safe to print back into a page.

    It corresponds to Unit 2 of the course, String Handling, which is allotted 5 lecture hours. The last section, on escaping, is short but is the most important in the unit, because the habit it teaches protects every page you write afterwards.

    Learning outcomes

    • Choose correctly between single quotes, double quotes and heredoc, and say exactly what each one does to $name and to \n.
    • Reach any character or slice of a string, and know why strlen() can disagree with the number of letters you can see.
    • Search a string safely — and say why strpos() demands === false.
    • Replace text with str_replace, and know when only a regular expression will do.
    • Format output with printf, sprintf and number_format.
    • Make user input safe to put back into a page with htmlspecialchars(), and explain what happens if you forget.

    2.1 Strings: the material of a web application¶

    The idea, first

    A web application is a string factory. The request arrives as text, every form field arrives as text — even a number typed into <input type="number"> arrives as the string "25" — the database hands rows back as text, and the reply that goes out is one long string of HTML. Unit 1 gave you the machinery; this unit gives you the material it works on.

    PHP has around a hundred string functions, and they have famously inconsistent names: str_replace has an underscore, strlen does not, strpos takes the haystack first and in_array takes the needle first. There is no rule; this is history rather than design. The way through it is not to memorise the list but to know the six questions you ever ask of a string — how long, what is at this position, does it contain, where is it, replace this, reformat it — and to know one function for each.

    One more idea underlies the whole unit and gets a section of its own: a string that came from a user and is going into a page is dangerous until you escape it. That is not a security aside; it is the difference between a page and a vulnerability, and the course asks for it under "validate server-side data".

    2.2 Creating a string¶

    Four ways to write a string literal. The choice is not cosmetic — it changes what happens to the contents.

    Form Variables? Escapes? Use it for
    'single' No Only \' and \\ Anything with no variables in it — slightly faster and never surprises you
    "double" Yes Yes — \n, \t, \", \$ The everyday choice
    <<<EOT heredoc Yes Yes A long block of HTML, quotes and all
    <<<'EOT' nowdoc No No A block that must stay literal — sample code, a template

    Listing 2.1. The quoting rules, side by side

    <?php
$name  = "Riya";
$marks = 91;

echo 'Single: Hello $name, you scored $marks\n';
echo "\n";
echo "Double: Hello $name, you scored $marks\n";

// Escapes that only work in double quotes
echo "Tab:\tafter\n";
echo "Quote: \"quoted\"\n";
echo "A literal dollar: \$name\n";
echo "Rupees: \u{20B9}500\n";

// Concatenation works with any of them
echo 'Joined ' . "with " . 'the dot operator' . "\n";

// .= appends — the workhorse when building HTML
$html = "";
$html .= "<ul>";
$html .= "<li>one</li>";
$html .= "</ul>";
echo $html, "\n";

    Output sent to the browser:

    Single: Hello $name, you scored $marks\n
Double: Hello Riya, you scored 91
Tab:    after
Quote: "quoted"
A literal dollar: $name
Rupees: ₹500
Joined with the dot operator
<ul><li>one</li></ul>

    Read the first two lines together: that is the whole difference. Single quotes give you exactly the characters you typed; double quotes give you a small language of substitutions.

    Interpolation, and when you need braces¶

    Listing 2.2. Curly braces inside double quotes

    <?php
$student = ["name" => "Aman", "marks" => [78, 82]];
$count   = 3;

echo "Plain variable:    $count\n";
echo "Array, no quotes:  $student[name]\n";        // works, but fragile
echo "Array, with braces: {$student['name']}\n";   // the form to use
echo "Nested:            {$student['marks'][1]}\n";

// Without braces PHP stops the name at the first character it cannot use:
echo "Plural: $counts\n";        // looks for $counts — a warning
echo "Plural: {$count}s\n";      // "3s"
echo "Plural: ${count}s\n";      // also works, older style

// Concatenation is always available and never ambiguous:
echo "Plural: " . $count . "s\n";

    Output:

    Plain variable:    3
Array, no quotes:  Aman
Array, with braces: Aman
Nested:            82

Warning:  Undefined variable $counts in interp.php on line 11
Plural:
Plural: 3s
Plural: ${count}s
Plural: 3s

    The rule that covers every case: if the thing after the $ is more than a plain variable name, wrap the whole expression in { }.

    Heredoc and nowdoc¶

    Listing 2.3. A block of HTML without escaping every quote

    <?php
$name   = "Riya Singh";
$roll   = 2231047;
$course = "Computer Science (Honours)";

echo <<<CARD
<div style="border:1px solid #bbb;border-radius:10px;padding:12px;max-width:340px">
  <h3 style="margin:0">$name</h3>
  <p style="margin:4px 0">Roll number: <b>$roll</b></p>
  <p style="margin:4px 0">$course</p>
</div>
CARD;

// A nowdoc keeps everything literal — useful for showing code on a page:
echo <<<'SAMPLE'
<pre>$name is not replaced here, and \n stays as two characters.</pre>
SAMPLE;

    Output sent to the browser:

    <div style="border:1px solid #bbb;border-radius:10px;padding:12px;max-width:340px">
  <h3 style="margin:0">Riya Singh</h3>
  <p style="margin:4px 0">Roll number: <b>2231047</b></p>
  <p style="margin:4px 0">Computer Science (Honours)</p>
</div><pre>$name is not replaced here, and \n stays as two characters.</pre>

    Heredoc is worth knowing for the moment you have twenty lines of HTML with attributes in double quotes. The closing marker must be at the start of its own line, with nothing after it but a semicolon.

    2.3 Accessing the content of a string¶

    Length, and one character at a time¶

    Listing 2.4. Indexing a string

    <?php
$s = "Dream University";

echo "length:      ", strlen($s), "\n";
echo "first:       ", $s[0], "\n";
echo "sixth:       ", $s[5], "\n";
echo "last:        ", $s[-1], "\n";
echo "last (long): ", $s[strlen($s) - 1], "\n";

// Walking every character
$vowels = 0;
for ($i = 0; $i < strlen($s); $i++) {
    if (strpos("aeiouAEIOU", $s[$i]) !== false) $vowels++;
}
echo "vowels:      $vowels\n";

// Writing a single character in place
$s[0] = "d";
echo "modified:    $s\n";

// str_split turns it into a real array
print_r(str_split("PHP", 1));

    Output:

    length:      16
first:       D
sixth:
last:        y
last (long): y
vowels:      6
modified:    dream University
Array
(
    [0] => P
    [1] => H
    [2] => P
)

    A string behaves like an array of characters for reading and writing, and negative indexes count from the end. Reading past the end gives a warning and an empty string, not a crash.

    strlen() counts bytes, not letters

    For plain English text they are the same. For anything else they are not: strlen("नमस्ते") is 18, because each Devanagari character takes three bytes in UTF-8. When the text may not be English, use the mb_ family — mb_strlen, mb_substr, mb_strtoupper — which count characters. This matters the day someone types their name in Hindi into your form.

    Listing 2.5. Bytes against characters

    <?php
$english = "Namaste";
$hindi   = "नमस्ते";
$emoji   = "PHP 🐘";

foreach (["english" => $english, "hindi" => $hindi, "emoji" => $emoji] as $label => $s) {
    printf("%-9s strlen=%-3d mb_strlen=%-3d  %s\n",
           $label, strlen($s), mb_strlen($s), $s);
}

echo "\nsubstr on Hindi cuts a character in half:\n";
echo "  substr:    ", substr($hindi, 0, 3), "\n";
echo "  mb_substr: ", mb_substr($hindi, 0, 3), "\n";

    Output:

    english   strlen=7   mb_strlen=7    Namaste
hindi     strlen=18  mb_strlen=6    नमस्ते
emoji     strlen=8   mb_strlen=6    PHP 🐘

substr on Hindi cuts a character in half:
  substr:    नमस
  mb_substr: नमस

    Rule of thumb: use the plain functions for things you generated yourself (codes, keys, HTML), and the mb_ functions for anything a human typed.

    Taking a piece out: substr¶

    Listing 2.6. substr, including the negative cases

    <?php
$roll = "22-BSC-CS-1045";

echo substr($roll, 0, 2),   "  <- year\n";
echo substr($roll, 3, 3),   "  <- degree\n";
echo substr($roll, -4),     "  <- serial (from the end)\n";
echo substr($roll, 3),      "  <- everything after the year\n";
echo substr($roll, 0, -5),  "  <- everything but the last five\n";
echo substr($roll, -7, 2),  "  <- two characters, seven from the end\n";

// A practical use: masking
$card = "4111111111111234";
echo "\nmasked card: ", str_repeat("*", strlen($card) - 4) . substr($card, -4), "\n";

$email = "zoya.khan@ex.ac.in";
$at = strpos($email, "@");
echo "user: ", substr($email, 0, $at), "   domain: ", substr($email, $at + 1), "\n";

    Output:

    22  <- year
BSC  <- degree
1045  <- serial (from the end)
BSC-CS-1045  <- everything after the year
22-BSC-CS  <- everything but the last five
CS  <- two characters, seven from the end

masked card: ************1234
user: zoya.khan   domain: ex.ac.in

    Two rules cover every use: a negative start counts from the end, and a negative length means "stop this many characters before the end".

    2.4 Searching the content of a string¶

    Question Function Returns
    Does it contain this? str_contains($h, $n) true / false — PHP 8, and it has no trap
    Where is it? strpos($h, $n) the position, or false — test with ===
    Where is it, ignoring case? stripos($h, $n) same
    Where is the last one? strrpos($h, $n) same
    Does it start / end with this? str_starts_with, str_ends_with boolean — PHP 8
    How many times? substr_count($h, $n) an integer
    Give me the rest from the match strstr($h, $n) the substring, or false
    Does it match a pattern? preg_match($re, $s) 1, 0 or false

    Listing 2.7. Every search function on one string

    <?php
$h = "the quick brown fox jumps over the lazy dog";
$n = "the";

echo "haystack: $h\n";
echo "needle:   $n\n\n";

var_dump(str_contains($h, $n));
var_dump(strpos($h, $n));          // 0 — the very first character
var_dump(strrpos($h, $n));         // 31 — the last occurrence
var_dump(stripos($h, "THE"));      // case-insensitive
var_dump(substr_count($h, $n));    // 2
var_dump(str_starts_with($h, "the"));
var_dump(str_ends_with($h, "dog"));
var_dump(strstr($h, "fox"));       // from the match onward
var_dump(strstr($h, "fox", true)); // before the match

echo "\nAnd the trap, one more time:\n";
if (strpos($h, $n) == false)  echo "  == says: NOT FOUND (wrong)\n";
if (strpos($h, $n) === false) echo "  === says: not found\n";
else                          echo "  === says: found at ", strpos($h, $n), "\n";

    Output:

    haystack: the quick brown fox jumps over the lazy dog
needle:   the

bool(true)
int(0)
int(31)
int(0)
int(2)
bool(true)
bool(true)
string(27) "fox jumps over the lazy dog"
string(16) "the quick brown "

And the trap, one more time:
  == says: NOT FOUND (wrong)
  === says: found at 0

    Changing the needle at the top changes every result. Look especially at what happens when the needle sits at position 0, because that is the case that breaks careless code.

    2.5 Replacing content¶

    Listing 2.8. str_replace, in all four shapes

    <?php
$s = "The UG course and the UG practical";

// 1. one thing for another
echo str_replace("UG", "U.G.", $s), "\n";

// 2. many things at once
echo str_replace(["UG", "and"], ["U.G.", "&"], $s), "\n";

// 3. many things, one replacement for all of them
echo str_replace(["UG", "practical"], "***", $s), "\n";

// 4. count how many were replaced
str_replace("UG", "U.G.", $s, $n);
echo "replaced $n times\n";

// case-insensitive version
echo str_ireplace("ug", "U.G.", $s), "\n";

// replace by position rather than by content
echo substr_replace("2231045", "XXXX", 0, 4), "\n";

// swap several things at once, longest key first — no double-replacement
echo strtr("I like PHP and PHP7", ["PHP7" => "PHP 8", "PHP" => "php"]), "\n";

    Output:

    The U.G. course and the U.G. practical
The U.G. course & the U.G. practical
The *** course and the *** ***
replaced 2 times
The U.G. course and the U.G. practical
XXXX045
I like php and PHP 8

    The fourth argument is by reference and is filled with the number of replacements — handy when you need to know whether anything happened.

    The double-replacement trap

    str_replace(["a","b"], ["b","c"], "ab") gives "cc", not "bc": the first pass turns both a's into b's, and the second pass then turns all the b's into c's. When replacements can feed each other, use strtr() with an array, which makes a single left-to-right pass.

    When you need a pattern: preg_replace¶

    str_replace matches exact text. When the thing to find has a shape rather than a fixed spelling — any run of spaces, any 10-digit number, any HTML tag — you need a regular expression.

    Listing 2.9. Regular expressions, the useful minimum

    <?php
$messy = "Example    College,\t\tDelhi   110019";

// \s+ = one or more whitespace characters of any kind
echo preg_replace('/\s+/', ' ', $messy), "\n";

// \d = a digit; {6} = exactly six of them
echo preg_replace('/\d{6}/', '[PIN]', $messy), "\n";

// Capture groups, referred to as $1, $2 in the replacement
echo preg_replace('/(\d{2})-(\d{2})-(\d{4})/', '$3-$2-$1', "Due 05-09-2026"), "\n";

// Testing rather than replacing
$tests = ["2231045", "22310", "abc1045"];
foreach ($tests as $t) {
    printf("%-10s roll number? %s\n", $t, preg_match('/^\d{7}$/', $t) ? "yes" : "no");
}

// Pulling pieces out
preg_match('/^(\w+)@([\w.]+)$/', "zoya.khan@ex.ac.in", $m);
print_r($m);

// Splitting on a pattern
print_r(preg_split('/[\s,]+/', "PHP, MySQL,jQuery   JSON"));

    Output:

    Example College, Delhi 110019
Example    College,     Delhi   [PIN]
Due 2026-09-05
2231045    roll number? yes
22310      roll number? no
abc1045    roll number? no
Array
(
)
Array
(
    [0] => PHP
    [1] => MySQL
    [2] => jQuery
    [3] => JSON
)

    The pattern is a string with delimiters, usually slashes, and optional flags after the closing one: i ignores case, m makes ^ and $ match each line.

    Pattern Matches Example use
    \d a digit 0–9 /^\d{7}$/ — a 7-digit roll number
    \w a letter, digit or underscore usernames
    \s a space, tab or newline /\s+/ — collapse whitespace
    . any character use sparingly
    [a-z] one character from the set /^[A-Za-z ]+$/ — a name
    ^ … $ start and end of the string anchor it, always
    + * ? one or more, zero or more, optional
    {3}, {2,4} exactly 3, between 2 and 4 /^\d{10}$/ — a phone number
    ( ) a capture group referred to as $1
    \| either /^(UG\|BA\|BCom)$/

    Anchor your patterns

    preg_match('/\d{7}/', "abc2231045xyz") returns 1 — the pattern is satisfied somewhere in the string. For validation you almost always want '/^\d{7}$/', which insists that the whole string is exactly seven digits. Forgetting the anchors is the most common validation bug on this course.

    2.6 Other built-in functions¶

    Case and trimming¶

    Listing 2.10. Cleaning up what a user typed

    <?php
$raw = "   riYA    SINGH   ";

echo "[", $raw, "]\n";
echo "[", trim($raw), "]\n";
echo "[", ltrim($raw), "]  <- left only\n";
echo "[", rtrim($raw), "]  <- right only\n";
echo "[", trim("###Riya###", "#"), "]  <- trim other characters too\n";

echo "\nupper:  ", strtoupper($raw), "\n";
echo "lower:  ", strtolower($raw), "\n";
echo "ucfirst:", ucfirst(strtolower(trim($raw))), "\n";
echo "ucwords:", ucwords(strtolower(trim($raw))), "\n";

// The full clean-up, in one line
$clean = ucwords(strtolower(preg_replace('/\s+/', ' ', trim($raw))));
echo "\ncleaned: [$clean]\n";

    Output:

    [   riYA    SINGH   ]
[riYA    SINGH]
[riYA    SINGH   ]  <- left only
[   riYA    SINGH]  <- right only
[Riya]  <- trim other characters too

upper:     RIYA    SINGH
lower:     riya    singh
ucfirst:Riya    singh
ucwords:Riya    Singh

cleaned: [Riya Singh]

    This four-line clean-up — trim, collapse spaces, fix the case — belongs at the top of every form handler you will write in Unit 3.

    Splitting and joining¶

    Listing 2.11. explode, implode, and the CSV pattern

    <?php
$line = "2231045,Zoya Khan,CS Hon,82";

$fields = explode(",", $line);
print_r($fields);

[$roll, $name, $course, $marks] = $fields;   // list assignment
echo "\n$name ($roll) scored $marks in $course\n";

// Back the other way
echo implode(" | ", $fields), "\n";

// The limit argument: keep the rest of the line intact
print_r(explode(",", $line, 3));

// A whole CSV file, in six lines
$csv = "roll,name,marks\n2231045,Zoya,82\n2231046,Aman,67";
$rows = explode("\n", $csv);
$head = explode(",", array_shift($rows));
foreach ($rows as $r) {
    print_r(array_combine($head, explode(",", $r)));
}

    Formatting numbers and columns¶

    Listing 2.12. printf, sprintf and number_format

    <?php
$items = [
    ["Tuition fee",   21000],
    ["Library",        1500],
    ["Examination",    2250.5],
];

printf("%-16s %12s\n", "Item", "Amount");
echo str_repeat("-", 29), "\n";
foreach ($items as [$label, $amount]) {
    printf("%-16s %12s\n", $label, number_format($amount, 2));
}
echo str_repeat("-", 29), "\n";
printf("%-16s %12s\n", "Total",
       number_format(array_sum(array_column($items, 1)), 2));

echo "\nPlaceholders:\n";
printf("  %%d integer      : %d\n", 42.9);
printf("  %%f float        : %f\n", 3.14159);
printf("  %%.2f 2 decimals : %.2f\n", 3.14159);
printf("  %%05d zero pad   : %05d\n", 42);
printf("  %%-10s left      : [%-10s]\n", "hi");
printf("  %%10s right      : [%10s]\n", "hi");
printf("  %%b binary       : %b\n", 10);
printf("  %%x hex          : %x\n", 255);
printf("  %%s of a bool    : [%s]\n", false);

$msg = sprintf("Dear %s, your total is Rs. %s.", "Riya", number_format(24750.5, 2));
echo "\n$msg\n";

    Output:

    Item                   Amount
-----------------------------
Tuition fee         21,000.00
Library              1,500.00
Examination          2,250.50
-----------------------------
Total               24,750.50

Placeholders:
  %d integer      : 42
  %f float        : 3.141590
  %.2f 2 decimals : 3.14
  %05d zero pad   : 00042
  %-10s left      : [hi        ]

  %s of a bool    : []

    printf prints; sprintf returns the string instead. Everything else about them is identical, and the format placeholders are the same as in C.

    number_format is for people, not for computers

    It returns a string with commas in it: "24,750.50". Feed that back into arithmetic and PHP reads it as 24. Format at the last moment, when the value is about to be printed, and never store the formatted version.

    Comparing strings¶

    Listing 2.13. Comparing, and the numeric-string trap

    <?php
var_dump("apple" == "apple");
var_dump("Apple" == "apple");          // case matters
var_dump(strcasecmp("Apple", "apple")); // 0 means equal

echo "\nstrcmp returns an ordering, not a boolean:\n";
var_dump(strcmp("apple", "banana"));   // negative: apple comes first
var_dump(strcmp("banana", "apple"));   // positive
var_dump(strcmp("apple", "apple"));    // 0

echo "\nThe trap — two numeric strings are compared as numbers:\n";
var_dump("10" == "1e1");
var_dump("0.0" == "0");
var_dump("abc" == 0);                  // false in PHP 8, true in PHP 5/7

echo "\nSo compare identifiers with === :\n";
var_dump("2231045" === "2231045");

echo "\nSorting names:\n";
$names = ["riya", "Aman", "zoya", "Bela"];
usort($names, "strcasecmp");
print_r($names);

    Output:

    bool(true)
bool(false)
int(0)

int(-1)
int(1)
int(0)

    The reference table¶

    Function Does Example → result
    strlen length in bytes strlen("Delhi") → 5
    mb_strlen length in characters for non-English text
    strtoupper / strtolower change case "DELHI" / "delhi"
    ucfirst / ucwords capitalise first letter / every word ucwords("riya singh") → "Riya Singh"
    trim / ltrim / rtrim remove surrounding characters trim(" x ") → "x"

    2.7 Making user text safe to print¶

    So far this unit has treated strings as text. The moment that text goes back into an HTML page, it stops being text: the browser reads it as markup. If a visitor can put <script> into your page, they can run code in every other visitor's browser. That is cross-site scripting, and it is the single most common flaw in student projects.

    Listing 2.14. The same input, with and without escaping

    <?php
// Imagine this came from a comment box:
$comment = 'Nice page <b>really</b> <img src=x onerror="alert(1)">';

echo "<h4>Printed straight out — the tags become part of the page</h4>";
echo "<div style='border:2px solid #c0392b;padding:8px'>$comment</div>";

echo "<h4>Escaped with htmlspecialchars — shown as text</h4>";
echo "<div style='border:2px solid #1a7f4b;padding:8px'>",
     htmlspecialchars($comment), "</div>";

echo "<h4>What escaping actually produced</h4>";
echo "<pre>", htmlspecialchars(htmlspecialchars($comment)), "</pre>";

    Output sent to the browser:

    <h4>Printed straight out — the tags become part of the page</h4><div style='border:2px solid #c0392b;padding:8px'>Nice page <b>really</b> <img src=x onerror="alert(1)"></div><h4>Escaped with htmlspecialchars — shown as text</h4><div style='border:2px solid #1a7f4b;padding:8px'>Nice page &lt;b&gt;really&lt;/b&gt; &lt;img src=x onerror=&quot;alert(1)&quot;&gt;</div><h4>What escaping actually produced</h4><pre>Nice page &amp;lt;b&amp;gt;really&amp;lt;/b&amp;gt; &amp;lt;img src=x onerror=&amp;quot;alert(1)&amp;quot;&amp;gt;</pre>

    The first box is a real vulnerability: the tags become part of the page. The second box shows the visitor exactly what they typed, as text. The only difference is one function call.

    Character Becomes Why it matters
    < &lt; cannot start a tag
    > &gt; cannot close one
    & &amp; cannot start an entity
    " &quot; cannot escape an attribute
    ' &#039; with ENT_QUOTES, which is the default since PHP 8.1

    The rule, in one line

    Escape on the way out, not on the way in. Store what the user actually typed; call htmlspecialchars() at the moment you echo it. Escaping on the way in means your database fills up with &amp; and you can never safely use the value anywhere else — in an email, say, or a PDF.

    2.8 Solved problems¶

    Example 2.1: Palindrome, three ways

    Problem. Write a function that reports whether a string is a palindrome, ignoring case, spaces and punctuation. Test it on "Madam", "A man, a plan, a canal: Panama" and "Delhi".

    Step 1 — normalise first

    "A man, a plan…" is a palindrome only after the spaces and punctuation are removed and the case is flattened. Do that once, at the top; comparing raw input is the mistake that makes this question look hard.

    Step 2 — the one-line answer

    $clean === strrev($clean). Reversing costs one extra copy of the string, which is irrelevant at this size.

    Step 3 — the two-pointer answer

    Compare the first and last characters, then step inwards. It stops at the first mismatch and uses no extra memory. This is the version an examiner asking for "an algorithm" wants.

    Answer. Madam ✓ A man, a plan, a canal: Panama ✓ Delhi ✗

    Listing 2.15. Palindrome — all three versions

    <?php
function normalise($s) {
    return preg_replace('/[^a-z0-9]/', '', strtolower($s));
}

// 1. strrev
function isPal1($s) {
    $c = normalise($s);
    return $c === strrev($c);
}

// 2. two pointers, no extra string
function isPal2($s) {
    $c = normalise($s);
    for ($i = 0, $j = strlen($c) - 1; $i < $j; $i++, $j--) {
        if ($c[$i] !== $c[$j]) return false;
    }
    return true;
}

// 3. recursion, for the sake of it
function isPal3($s) {
    $c = normalise($s);
    if (strlen($c) < 2) return true;
    if ($c[0] !== $c[strlen($c) - 1]) return false;
    return isPal3(substr($c, 1, -1));
}

foreach (["Madam", "A man, a plan, a canal: Panama", "Delhi", "", "x"] as $t) {
    printf("%-32s %s %s %s\n", '"' . $t . '"',
        isPal1($t) ? "Y" : "n", isPal2($t) ? "Y" : "n", isPal3($t) ? "Y" : "n");
}

    Example 2.2: Count vowels, consonants, digits and spaces

    Problem. For any sentence, report how many vowels, consonants, digits, spaces and other characters it contains.

    Step 1 — one pass, one decision per character

    Walk the string once. For each character ask, in order: is it a digit, a space, a letter? Only if it is a letter does the vowel/consonant question arise. Asking in the wrong order double-counts.

    Step 2 — testing membership

    strpos("aeiou", $ch) !== false works and is the classic answer; in_array($ch, ['a','e','i','o','u']) reads better; and ctype_alpha(), ctype_digit() and ctype_space() answer the other three questions directly.

    Step 3 — count from the counts

    Consonants are letters minus vowels; there is no need to test twice. "Other" is the total minus everything else, which also guarantees the columns add up.

    Answer. For "Dream University 2026!": vowels 6, consonants 9, digits 4, spaces 2, other 1 — and 6+9+4+2+1 = 22, the length of the string

    Listing 2.16. Character census

    <?php
function census($s) {
    $c = ["vowels" => 0, "consonants" => 0, "digits" => 0, "spaces" => 0, "other" => 0];

    for ($i = 0; $i < $len; $i++) {
        $ch = strtolower($s[$i]);

            else                                $c["consonants"]++;
        }
        else $c["other"]++;
    }
    $c["total"] = $len;
    return $c;
}

    Example 2.3: Title case that respects small words

    Problem. Convert "the story of php and mysql in delhi" to title case, but leave words like "of", "and", "in" lower case unless they are the first word.

    Step 1 — why ucwords is not enough

    ucwords() capitalises every word, giving "The Story Of PHP And MySQL In Delhi". The requirement is a list of exceptions, so a plain library call cannot do it.

    Step 2 — split, map, join

    Split on spaces, decide for each word, join back. The decision is: if this is the first word, capitalise; else if it is in the small-word list, leave it; else capitalise.

    Step 3 — the index matters

    foreach ($words as $i => $w) gives the position, which is what makes "the first word is always capitalised" expressible.

    $small = ["a", "an", "and", "of", "the", "in", "on", "for", "to", "with", "or"];

    Example 2.4: A validation function that reports every error

    Problem. Validate a registration record: name (letters and spaces only, at least 3 characters), roll number (exactly 7 digits), email, and phone (exactly 10 digits starting 6–9). Return all the problems, not just the first.

    Step 1 — collect, do not return early

    A form that reports one error at a time is infuriating. Build an array of messages keyed by field and return the array; an empty array means valid.

    Step 2 — one pattern per rule, anchored

    Every pattern gets ^ and $. Without them, "abc2231045xyz" passes the roll-number test.

    2.9 Common mistakes to avoid¶

    • Do not expect 'single quotes' to interpolate. If a variable does not appear in the output, look at the quotes first.
    • Do not use + to join strings. PHP uses .; "a" + "b" is arithmetic and gives 0 with a warning.
    • Do not test strpos() with ==. A match at position 0 is indistinguishable from failure.
    • Do not forget ^ and $ in a validation pattern. Unanchored patterns accept anything with the right shape buried in it.
    • Do not use strlen() on text a human typed in a non-English script. Use mb_strlen().
    • Do not do arithmetic on the output of number_format(). It is a display string with commas in it.
    • Do not escape on input. Store the real value and call htmlspecialchars() when echoing.
    • Do not use md5() for passwords. Use password_hash() and password_verify() — md5 is fine for a checksum and useless for a secret.
    • Do not forget that explode takes the separator first and in_array takes the needle first. When in doubt, look it up rather than guess — the argument order in PHP's string library genuinely is inconsistent.
    • Do not chain string functions so deeply that you cannot debug them. Three lines with names beat one line with six nested calls.

    2.10 Summary¶

    The key points of the unit, each stated as something you should now be able to do.

    • You can choose a quoting style on purpose: single quotes for literal text, double quotes for interpolation and escapes, heredoc for a block, nowdoc when nothing should be substituted — and you know to reach for { } the moment an array element appears inside a string.
    • You can reach into a string by index, including from the end, take slices with substr() using both negative start and negative length, and you know that strlen() counts bytes while mb_strlen() counts characters.
    • You can search a string six different ways and you know which of them can return a value that == confuses with false.
    • You can replace exact text with str_replace(), avoid the double-replacement trap with strtr(), and reach for preg_replace() when what you are matching has a shape rather than a spelling.
    • You can write the handful of regular expressions this course needs — anchored, with \d, \w, \s, character classes and quantifiers — and you know that forgetting ^ and $ is what makes a validator accept rubbish.
    • You can format for a human with printf, sprintf and number_format, and you know the formatted value is a display string that must never go back into arithmetic.
    • You can make any user-supplied text safe to place in a page with htmlspecialchars(), you can say what it converts and why, and you know the rule is to escape on the way out.
    • Above all you have the six questions — how long, what is here, does it contain, where is it, replace this, reformat it — and one reliable function for each, which is what makes the other ninety string functions lookup-able rather than memorisable.

    • (a) Store the raw text; call htmlspecialchars() when echoing it
    • (b) Call htmlspecialchars() before storing, then echo it directly
    • (c) Call strip_tags() before storing
    • (d) Nothing is needed if the field is a textarea
    Answer

    The answer is (a).

    • (a) Correct. Escape on output. The stored value stays usable for email, exports and search.
    • (b) It works on the page but corrupts the stored value: an email would show &amp;, and searching for "AT&T" would fail.
    • (c) This silently destroys legitimate input — a maths comment containing 5 < 6 loses characters.
    • (d) The input element makes no difference; anything can be posted to your script.

    Exercise 2.17. echo number_format(1234.5678, 2) + 1; prints:

    • (a) 1235, with a warning
    • (b) 2, with a warning about a non-numeric value
    • (c) 1235.57
    • (d) A TypeError
    Answer

    The answer is (b).

    • (a) This assumes the formatted string converts back to 1234.57. It does not: conversion stops at the first character that cannot be part of a number, and that is the comma.
    • (b) Correct. Correct. "1,234.57" converts to the number 1 because conversion stops at the comma. This is why you format only at the moment of printing.
    • (c) That would require the formatted string to convert back cleanly, which the thousands separator prevents.
    • (d) PHP 8 throws for a wholly non-numeric string, but "1,234.57" is leading-numeric, so it warns and continues.

    Write it — string workshop¶

    Exercise 2.18. Write initials($name), which turns a full name into upper-case initials separated by full stops. Extra spaces must not produce empty initials.

    Expected output:
    R.S.
    Z.K.
    A.B.C.

    Starting point:

    <?php
function initials($name) {
    // your code here
}

foreach (["Riya Singh", "  zoya   khan ", "a b c"] as $n) {
    echo initials($n), "\n";
}

    Your script is tested with these cases:

    Case Expected output
    three names R.S.
    Z.K.
    A.B.C.
    Answer

    A solution:

    <?php
function initials($name) {
    $parts = preg_split('/\s+/', trim($name));
    $out = "";
    foreach ($parts as $p) {
        if ($p !== "") $out .= strtoupper($p[0]) . ".";
    }
    return $out;
}

foreach (["Riya Singh", "  zoya   khan ", "a b c"] as $n) {
    echo initials($n), "\n";
}

    preg_split('/\s+/', …) rather than explode(" ", …) is what makes the double spaces harmless — explode would hand back empty strings between them.

    The trailing full stop is part of the specification here, which is why the separator is appended rather than joined with implode.

    Exercise 2.19. Write excerpt($text, $limit) that shortens text to at most $limit characters without cutting a word in half, adding … when it shortened anything. Text already short enough must come back untouched, with no ellipsis.

    Expected output:
    Advanced Web…
    Short text

    Starting point:

    <?php
function excerpt($text, $limit) {
    // your code here
}

echo excerpt("Advanced Web Programming for beginners", 15), "\n";
echo excerpt("Short text", 15), "\n";

    Your script is tested with these cases:

    Case Expected output
    long and short Advanced Web…
    Short text
    Answer

    A solution:

    <?php
function excerpt($text, $limit) {
    if (strlen($text) <= $limit) return $text;
    $cut = substr($text, 0, $limit);
    $space = strrpos($cut, " ");
    if ($space !== false) $cut = substr($cut, 0, $space);
    return rtrim($cut) . "…";
}

echo excerpt("Advanced Web Programming for beginners", 15), "\n";
echo excerpt("Short text", 15), "\n";

    strrpos finds the last space in the cut piece — the word boundary to fall back to. The !== false matters: a limit that lands inside the first word leaves no space at all.

    This is the function behind every "read more" link, and the early return for short text is what stops it adding an ellipsis to a complete sentence.

    Exercise 2.20. Write strongPassword($p) returning true only when the password is at least 8 characters and contains an upper-case letter, a lower-case letter, a digit and a symbol. Print yes or no for each test password.

    Expected output:
    no
    no
    yes

    Starting point:

    <?php
function strongPassword($p) {
    // your code here
}

foreach (["delhi", "Delhi2026", "Delhi@2026"] as $p) {
    echo strongPassword($p) ? "yes" : "no", "\n";
}

    Your script is tested with these cases:

    Case Expected output
    three passwords no
    no
    yes
    Answer

    A solution:

    <?php
function strongPassword($p) {
    if (strlen($p) < 8) return false;
    if (!preg_match('/[A-Z]/', $p)) return false;
    if (!preg_match('/[a-z]/', $p)) return false;
    if (!preg_match('/[0-9]/', $p)) return false;
    if (!preg_match('/[^A-Za-z0-9]/', $p)) return false;
    return true;
}

foreach (["delhi", "Delhi2026", "Delhi@2026"] as $p) {
    echo strongPassword($p) ? "yes" : "no", "\n";
}

    Five small unanchored patterns, each asking "does this kind of character appear anywhere?". This is one of the rare cases where you deliberately do not anchor. A single monster pattern with lookaheads exists, but nobody can read it six months later.

    Note that each rule returns false immediately. Writing it as one enormous boolean expression makes it impossible to tell the user which rule they broke — and in Unit 3 you will want to.

    Exercise 2.21. Write a script that counts the words, characters and sentences in a paragraph. Sentences end with ., ! or ?.

    Answer 
    <?php
$text = "PHP is fun. Is it easy? Yes! Try it, then decide.";

$words     = str_word_count($text);

    preg_match_all returns the number of matches, and the + makes a run such as ?! count once. For non-English text use mb_strlen in place of strlen so that characters, not bytes, are counted.

    Exercise 2.22. Given "2231045,Zoya Khan,CS Hon,82", print an HTML table row with the marks right-aligned and every field escaped. (Think: explode, then htmlspecialchars in a loop.)

    Exercise 2.23. Write capitaliseSentences($text) that upper-cases the first letter of every sentence and leaves the rest alone.

    Answer 
    <?php
function capitaliseSentences(string $text): string {
    return preg_replace_callback('/(^|[.!?]\s+)([a-z])/', function ($m) {
        return $m[1] . strtoupper($m[2]);
    }, $text);
}

echo capitaliseSentences("hello there. how are you? fine! thanks.");

    Hello there. How are you? Fine! Thanks.

    The pattern finds a lower-case letter that is either at the very start of the string or follows a sentence-ending mark and some whitespace; the callback upper-cases that letter and puts back what came before it.

    Exercise 2.24. Write a function that checks whether two strings are anagrams, ignoring case and spaces. (Hint: sort the characters of both and compare.)

    Answer 
    <?php
function isAnagram(string $a, string $b): bool {
    $normalise = function (string $s): string {
        $s = strtolower(preg_replace('/\s+/', '', $s));
        $chars = str_split($s);
        sort($chars);
        return implode('', $chars);
    };
    return $normalise($a) === $normalise($b);
}

var_dump(isAnagram("Dormitory", "Dirty room"));   // bool(true)
var_dump(isAnagram("Delhi", "Hill"));             // bool(false)

    Two strings are anagrams exactly when their letters, once case and spaces are removed and the letters sorted, form the same string.

    Exercise 2.25. What is the difference between strstr($s, "@") and substr($s, strpos($s, "@"))? What happens to each when the @ is absent?

    Answer

    When the @ is present, both return the same thing: for "zoya@ex.ac.in" each gives "@ex.ac.in".

    When it is absent, they differ:

    • strstr($s, "@") returns false, which is the honest answer "not found".
    • strpos returns false as well, but substr($s, false) converts false to the start position 0 and quietly returns the whole string. For "zoya.ex.ac.in" the result is "zoya.ex.ac.in", which looks like a valid answer and is not.

    So strstr is the safer form; with strpos the result must be tested with === false before it is used.

    Exercise 2.26. Write maskEmail("zoya.khan@ex.ac.in") that gives "z*******n@ex.ac.in".

    Answer 
    <?php
function maskEmail(string $email): string {
    [$local, $domain] = explode("@", $email, 2);
    $n = strlen($local);
    if ($n <= 2) {
        return str_repeat("*", $n) . "@" . $domain;
    }
    return $local[0] . str_repeat("*", $n - 2) . $local[$n - 1] . "@" . $domain;
}

echo maskEmail("zoya.khan@ex.ac.in");   // z*******n@ex.ac.in

    The local part zoya.khan has nine characters, so the first and last are kept and seven asterisks fill the middle. The $n <= 2 guard stops the function from revealing a very short name.

    Exercise 2.27. Explain why preg_replace('/\s+/', ' ', $s) is safer than str_replace(" ", " ", $s) for collapsing spaces.

    Answer

    str_replace(" ", " ", $s) replaces each pair of spaces by one space in a single pass and then stops, so a longer run is only shortened: "a b" (four spaces) becomes "a b" (two). It also knows nothing about tabs and newlines.

    preg_replace('/\s+/', ' ', $s) matches an entire run of any whitespace, of any length, and replaces it by exactly one space, so "a b\t\tc" becomes "a b c" in one call.

    Exercise 2.28. Write a script that reads a comma-separated list of marks in a string and prints the highest, lowest and average, ignoring any entries that are not numeric.

    Answer 
    <?php
$input = "82, 67, abc, 91, , 55, 88x";

$marks = [];
foreach (explode(",", $input) as $piece) {
    $piece = trim($piece);
    if (is_numeric($piece)) {
        $marks[] = $piece + 0;
    }
}

if ($marks) {
    echo "Highest: ", max($marks), "\n";
    echo "Lowest: ", min($marks), "\n";
    echo "Average: ", round(array_sum($marks) / count($marks), 2), "\n";
} else {
    echo "No valid marks\n";
}

    Highest: 91
Lowest: 55
Average: 73.75

    abc, the empty entry and 88x are skipped because is_numeric rejects them. The if ($marks) test avoids a division by zero when nothing valid was entered.

    Examination questions¶

    These are questions in the shapes this course uses, grouped by the marks they carry. A two-mark question wants a definition and one concrete example, a five-mark question wants structure, and a ten-mark question wants an answer with parts.

    Two-mark questions¶

    Exercise 2.29. (2 marks) Difference between single-quoted and double-quoted strings.

    Answer

    A double-quoted string interpolates variables and processes escape sequences; a single-quoted string does neither, honouring only \' and \\.

    $n = 5;
echo "Total: $n\n";     // Total: 5   then a newline
echo 'Total: $n\n';     // Total: $n\n   literally

    Exercise 2.30. (2 marks) What does strpos() return when the needle is not found, and why is that a problem?

    Answer

    It returns false. The problem is that a match at the first character returns 0, and 0 == false is true — so a loose comparison reports "not found" for a string that begins with the needle.

    if (strpos($s, $x) === false) { /* genuinely absent */ }

    Since PHP 8 there is str_contains($s, $x), which returns a boolean and has no such trap.

    Exercise 2.31. (2 marks) What is the difference between strlen() and mb_strlen()?

    Answer

    strlen() counts bytes; mb_strlen() counts characters. They agree for plain English and disagree for anything else, because UTF-8 uses several bytes per character.

    echo strlen("नमस्ते");     // 18
echo mb_strlen("नमस्ते");  // 6

    Use the mb_ family for anything a human typed.

    Exercise 2.32. (2 marks) Name any four string functions and say what each does.

    Answer
    • strlen($s) — length in bytes
    • strtoupper($s) / strtolower($s) — change case
    • trim($s) — remove whitespace from both ends
    • substr($s, 0, 5) — take a piece
    • str_replace($find, $with, $s) — replace text
    • ucwords($s) — capitalise the first letter of every word
    • explode($sep, $s) / implode($glue, $a) — string to array and back

    Exercise 2.33. (2 marks) What does htmlspecialchars() do, and why is it needed?

    Answer

    It converts the characters that have meaning in HTML into entities: < to &lt;, > to &gt;, & to &amp;, " to &quot;.

    It is needed whenever text that came from a user is echoed into a page. Without it, a visitor who types <script>…</script> gets that script executed in every other visitor's browser — a cross-site scripting (XSS) attack.

    Exercise 2.35. (10 marks) Write a PHP program with buttons that perform six string operations: length, substring, replace, trim, check if a value is a string, and capitalise each word.

    Answer

    The design point worth stating: give every button the same name and a different value, so only the one pressed is submitted and a single switch handles all six.

    <?php
$text = $_POST["text"] ?? "  the quick brown fox  ";
$op   = $_POST["op"] ?? "";
$result = "";

switch ($op) {
    case "length":   $result = strlen($text);                    break;
    case "sub":      $result = substr($text, 3, 5);              break;
    case "replace":  $result = str_replace("quick", "slow", $text); break;
    case "trim":     $result = "[" . trim($text) . "]";          break;
    case "isstring": $result = is_string($text) ? "true" : "false"; break;
    case "ucwords":  $result = ucwords($text);                   break;
}
?>

<form action="" method="post">
  <input type="text" name="text" size="40"
         value="<?= htmlspecialchars($text, ENT_QUOTES) ?>">

  <button type="submit" name="op" value="length">Length</button>
  <button type="submit" name="op" value="sub">Substring</button>
  <button type="submit" name="op" value="replace">Replace</button>
  <button type="submit" name="op" value="trim">Trim</button>
  <button type="submit" name="op" value="isstring">Is string?</button>
  <button type="submit" name="op" value="ucwords">Capitalise</button>
</form>

<?php if ($op): ?>
  <p>Result: <b><?= htmlspecialchars((string) $result) ?></b></p>
<?php endif; ?>

    Two marks are usually reserved for details: printing the trim result inside square brackets so the removed spaces are visible, and escaping the value put back into the text box so a quotation mark cannot break the attribute.
