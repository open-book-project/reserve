    Glossary and Further Reading¶

    Glossary¶

    AJAX. Asking the server for data in the background, with JavaScript, and updating part of the page without reloading it (Unit 5).

    Anchor (regular expression). The symbols ^ and $, which tie a pattern to the start and the end of the string; without them a validation pattern matches somewhere in the input rather than all of it (Section 2.5).

    Array. PHP's one compound structure: an ordered map from keys to values. With integer keys 0, 1, 2 … it behaves as a list; with chosen keys it is an associative array (Section 1.6).

    Callback. A function passed to another function, to be called later; in jQuery, the function that runs when a request has finished or an event has occurred (Unit 5).

    Casting. Converting a value to another type on purpose, as in (int)"12" (Section 1.5).

    Client side and server side. Code that runs in the visitor's browser (HTML, CSS, JavaScript, jQuery) as against code that runs on the web server before the reply is sent (PHP). The browser never receives PHP (Section 1.1).

    Cookie. A small piece of data that the server asks the browser to store and to send back with later requests (Section 3.10).

    CRUD. The four operations on stored data: create, retrieve (read), update and delete. In SQL they are INSERT, SELECT, UPDATE and DELETE (Unit 4).

    Cross-site scripting (XSS). A flaw in which text supplied by one visitor is printed unescaped into a page and run as script in the browsers of other visitors. The defence is to escape output (Section 2.7).

    Database. An organised collection of tables that a database server such as MySQL stores and answers questions about (Unit 4).

    Debounce. Waiting until a burst of events, such as typing, has paused before acting on it, so that one request is sent instead of one per keystroke (Unit 5).

    Delegation. Attaching an event handler to an element that always exists, such as a list, so that it also handles clicks on children that were added later (Section 5.5).

    DOM. The Document Object Model: the tree of elements that the browser builds from a page, which JavaScript and jQuery read and change (Unit 5).

    Escaping. Replacing the characters that have a special meaning in a context (for HTML, <, >, & and the quotation marks) by harmless equivalents. In PHP, htmlspecialchars() (Section 2.7).

    Foreign key. A column whose values are primary-key values of another table, such as students.course pointing to courses.code (Section 4.2).

    GET and POST. The two ways a form sends its values: appended to the address (GET), or in the body of the request (POST) (Unit 3).

    Heredoc. A way of writing a long string with quotation marks in it, between <<<EOT and a closing marker (Section 2.2).

    htdocs. The folder of a XAMPP installation from which the Apache server serves files (Section 1.2).

    Interpolation. The substitution of the value of a variable into a double-quoted string (Section 2.2).

    JOIN. An SQL operation that combines rows of two tables whose key columns match; INNER JOIN keeps only matches and LEFT JOIN keeps every row of the left table (Section 4.5).

    JSON. JavaScript Object Notation: a text format for objects, arrays, strings, numbers, booleans and null, used to carry data between server and browser. PHP produces it with json_encode and reads it with json_decode (Section 5.6).

    jQuery. A JavaScript library that selects elements, changes them, handles events and makes AJAX calls with short, uniform syntax (Unit 5).

    Localhost. The name by which your own computer refers to itself; the address http://localhost/ reaches the web server running on it (Section 1.2).

    mysqli. The PHP extension used throughout this book to talk to MySQL, in a procedural and an object-oriented style (Section 4.7).

    NULL. The value of a variable that has none; in a database, "no value recorded", which is neither zero nor the empty string (Sections 1.5 and 4.2).

    Post/redirect/get. The pattern of finishing a successful POST with a redirect, so that refreshing the resulting page does not submit the form again (Section 3.10).

    Prepared statement. An SQL statement sent to the server with placeholders, and the values sent separately, so that the values can never be read as SQL (Section 4.10).

    Primary key. The column, or columns, that identify a row uniquely; never repeated and never null (Section 4.2).

    Query string. The part of an address after the ?, holding name=value pairs separated by & (Section 3.3).

    Result set. The rows returned by a SELECT, which PHP reads one at a time with a fetch function (Section 4.7).

    Sanitising. Transforming a value so that it is safe in the place where it is about to be used; compare with validating, which decides whether a value is acceptable at all (Section 3.8).

    Selector. In jQuery, a string such as "#id", ".class" or "tr:even" that chooses the elements to work on (Section 5.3).

    Session. Data about a visitor that the server keeps between requests, found again by an identifier that the browser sends in a cookie (Section 3.10).

    SQL. Structured Query Language, the language in which a relational database is asked questions and given instructions (Unit 4).

    SQL injection. An attack in which text typed by a visitor becomes part of an SQL statement and changes its meaning. A prepared statement prevents it (Section 4.10).

    Superglobal. A built-in PHP array available in every scope, such as $_GET, $_POST, $_SERVER, $_SESSION and $_FILES (Section 3.5).

    Type juggling. PHP's automatic conversion of a value to the type an operator needs, the source of many surprises in comparisons (Section 1.5).

    Validation. Checking on the server that a submitted value is acceptable and rejecting it if it is not. Client-side checks are a convenience; only the server's check counts (Section 3.7).

    XAMPP. A bundle of the Apache web server, MySQL (MariaDB), PHP and Perl for a personal computer (Section 1.2).

    Further reading¶

    The books named in the course outline.

    Book Best for
    R. Nixon, Learning PHP, MySQL & JavaScript with jQuery, CSS and HTML5, O'Reilly, 2018 The whole course in one book; the closest match to this course
    S. Holzner, PHP: The Complete Reference, McGraw Hill, 2017 Looking a function up; the reference to keep open
    J. Murach, Murach's PHP and MySQL, 2nd edition, 2014 Units 3 and 4: forms and database work, laid out page by page
    J. Duckett, JavaScript and jQuery, Wiley, 2014 Unit 5, and the clearest pictures of the DOM in print

    Web references named in the course outline. w3schools.com/php and tutorialspoint.com/php. The authoritative reference for every function is the PHP manual at php.net/manual, where each function page has user-contributed examples at the foot.

    The course outline. The course outline is issued by the institution that teaches the course; ask your teacher for the current edition.

    Where to start¶

    A reader who has never written PHP should begin with Unit 1 and read straight through, running every listing. A reader who knows the language and has an examination close should work through the Summary of each unit, then the multiple-choice and predict-the-output exercises, then the examination questions, and keep the Reference unit beside them.
