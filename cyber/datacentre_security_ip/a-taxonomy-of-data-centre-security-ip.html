    Chapter 5: A Taxonomy of Data-Centre Security IP¶

    With the facility and the threats in view, we can now name the building blocks. Most of them are delivered as licensable silicon IP integrated into SoCs, as discrete chips on the board, or as firmware running on either, and the same function, for example a root of trust, can appear in all three forms in one server. This chapter defines each class of security IP, then explains the roles into which standards divide the root of trust and why a server contains more than one.

    5.1 The classes of security IP¶

    Security IP class What it does Typical implementations
    Hardware root of trust (RoT) Immutable first code plus protected keys; the anchor for secure boot, measurement, identity and recovery Integrated: Caliptra, OpenTitan Darjeeling, AMD ASP, Intel CSME, Arm RSE, NVIDIA GPU security processor, Synopsys tRoot, Rambus RT-6xx, Secure-IC Securyzr. Discrete: Lattice, Microchip, ASPEED, Nuvoton, Axiado, Titan, Cerberus, OpenTitan Earl Grey
    Secure and measured boot ROM Verifies (secure) or hashes and records (measured) each boot stage Every RoT; CPU microcode and ACM; UEFI Secure Boot; U-Boot verified boot
    DICE engine Derives per-boot device identities (CDIs) from a unique device secret and code measurements TCG DICE in Caliptra, the OpenTitan key manager, NVIDIA GPUs, Microsoft and Google RoTs, Microchip, Lattice
    TPM 2.0 Standardised RoT for storage and reporting: PCRs, sealed keys, quotes Discrete: Infineon OPTIGA, Nuvoton NPCT, STMicro ST33. Firmware: Intel PTT, AMD fTPM. Virtual: vTPM, NitroTPM
    HSM Tamper-responsive key vault with FIPS 140-3 Level 3 or 4 validation Thales Luna, Entrust nShield, Utimaco, Marvell LiquidSecurity, Futurex, Securosys, IBM CEX, Azure Integrated HSM
    Key storage and entropy OTP and eFuse arrays, PUF (silicon fingerprint), TRNG and DRBG, key ladders, key vaults Synopsys (OTP NVM, QuiddiKey PUF), eMemory and PUFsecurity, Crypto Quantique, Rambus, Arm, OpenTitan CSRNG
    Crypto accelerators AES, SHA-2 and SHA-3, HMAC, RSA and ECC public-key engines, SM2, SM3, SM4 Synopsys, Rambus, Cadence and Secure-IC, Arm CryptoCell, Silex Insight, CAST, Xiphera
    PQC accelerators ML-KEM (FIPS 203), ML-DSA (FIPS 204), SLH-DSA (FIPS 205), LMS and XMSS (SP 800-208) Adams Bridge (Caliptra), PQShield, Rambus QSE, Synopsys Agile PQC, Secure-IC, CAST KiviPQC, Xiphera, SEALSQ QS7001
    Inline memory encryption Encrypts DRAM traffic per VM or TEE (AES-XTS, sometimes with integrity) Intel TME-MK, AMD SME and SEV, Arm MEC; licensable IP from Synopsys and Rambus
    Link encryption engines PCIe and CXL IDE, MACsec, IPsec, PSP, NVLink and UALink encryption Synopsys, Rambus, Cadence, Alphawave Semi IDE modules; NVIDIA, Broadcom, Marvell, Microchip silicon
    TEE or confidential computing Hardware-isolated execution with remote attestation Intel SGX and TDX, AMD SEV-SNP, Arm CCA, IBM Secure Execution, NVIDIA GPU CC, RISC-V CoVE (emerging)
    Attestation responder Signs measurements for a remote verifier (SPDM, DICE certificates, TPM quotes) DMTF SPDM stacks (libspdm), Caliptra runtime, NVIDIA GPU firmware, NIC and SSD firmware
    Lifecycle and debug control Enforces manufacturing, production and RMA states; locks JTAG OpenTitan life-cycle controller, Caliptra lifecycle, Arm CoreSight authentication, vendor secure-debug IP
    Anti-tamper and side-channel countermeasures Voltage, clock, temperature, laser and EM sensors, active shields, DPA masking OpenTitan sensor controller, Secure-IC Digital Sensor, Synopsys, Rambus; Riscure and eShard test tools
    Secure management controller BMC or SCM with secure boot, attestation and a hardened OS ASPEED AST2600 and AST2700, Nuvoton NPCM8xx, Axiado TCU, Microsoft Hydra, HPE iLO 7, Dell iDRAC

    5.2 Roles of the root of trust¶

    NIST SP 800-193 and the TCG split "the root of trust" into roles, and one chip may implement several of them. Distinguishing the roles explains why a server contains more than one RoT.

    Role Responsibility Typical home
    RTM: Root of Trust for Measurement Takes the first measurement of mutable code CPU boot ROM and microcode, Caliptra core, DICE engine
    RTS: Root of Trust for Storage Shielded storage of keys and measurements TPM, Caliptra key and PCR vaults, OpenTitan OTP and flash
    RTR: Root of Trust for Reporting Signs measurement reports (quotes, SPDM measurements) TPM, Caliptra runtime, GPU and NIC firmware
    RTU: Root of Trust for Update Authenticates firmware updates and prevents rollback PRoT, BMC, Caliptra MCU, device ROM
    RTRec: Root of Trust for Recovery Restores known-good firmware after corruption PRoT with golden image, OCP Recovery and streaming boot
    RTD: Root of Trust for Detection Detects corruption at boot and at run time PRoT SPI and SMBus monitors, BMC, fleet attestation

    5.3 Discrete versus integrated¶

    A discrete platform RoT is a separate chip that can hold other chips in reset and physically interpose on their flash. It protects devices that lack their own RoT and it survives a compromised host. An integrated RoT sits inside the SoC boundary, so it can measure the SoC's own firmware and protect keys from board-level probing. The industry direction, championed by OCP and Caliptra, is an integrated RoT in every major chip, plus a platform RoT that aggregates and attests them.

    5.4 Summary¶

    • Security IP comes as licensable silicon IP, discrete chips or firmware, and one function (such as a root of trust) can appear in all three forms in one server.
    • The classes include RoTs, boot ROMs, DICE, TPMs, HSMs, key stores, crypto and PQC accelerators, memory and link encryption, TEEs, attestation responders, lifecycle control, anti-tamper and secure management controllers.
    • NIST SP 800-193 and TCG split the RoT into roles: measurement, storage, reporting, update, recovery and detection.
    • A discrete RoT holds other chips in reset and survives a compromised host; an integrated RoT measures its own SoC. The direction is both: an integrated RoT in every chip plus a platform RoT that aggregates them.

    5.5 Exercises¶

    1. What does the RTM role do, and where does it typically live?

      Answer

      The Root of Trust for Measurement takes the first measurement of mutable code. It lives in the CPU boot ROM and microcode, the Caliptra core or a DICE engine.

    2. Why does a server contain more than one root of trust?

      Answer

      Different roles and different chips need different anchors: a discrete platform RoT protects the flash of devices that lack their own, integrated RoTs measure each SoC, and a TPM or HSM holds sealed keys. One chip may implement several roles, but no single one covers all of them.

    3. State one advantage of a discrete PRoT and one of an integrated RoT.

      Answer

      Discrete: it can hold other chips in reset and interpose on their flash, protecting devices without their own RoT and surviving a compromised host. Integrated: it can measure the SoC's own firmware and protect keys from board-level probing.

    4. Which class of security IP converts a device secret and code measurements into a per-boot identity?

      Answer

      The DICE engine, which derives compound device identifiers (CDIs) from the unique device secret and measurements of the code.
