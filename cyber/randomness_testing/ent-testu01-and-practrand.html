    Chapter 8: ENT, TestU01 and PractRand¶

    The last three tools in the survey sit at three different points on a scale. ENT is a small command-line program that prints five statistics on any file, with no verdict. TestU01 is a C library whose largest battery is among the most demanding available, and it comes in three levels, SmallCrush, Crush and BigCrush. PractRand does not fix the amount of data in advance: it tests as you feed it and tells you how much data it took for a flaw to appear. Together they show how test power depends on how much data you are willing to spend.

    8.1 About ENT¶

    John Walker's ENT (the page we read is dated 28 January 2008, and the program is public domain) is a small command-line tool that reports five statistics on any file of bytes, a quick look that also hints at how well a file might compress. It needs no fixed amount of data, though some values, such as pi, converge slowly and benefit from large files. It gives no verdict. It prints numbers, and you read them with judgement.

    8.2 Entropy (ENT)¶

    The idea in plain words. How many bits of information does each byte carry, if we look at bytes on their own? Full randomness gives 8. Text gives far less. It is like asking how evenly used the letters in a language are, ignoring what order they come in.

    Example 8.2: Entropy (ENT)

    The bytes 1, 2, 3, 4, 1, 2, 3, 4 have four equally common values, so the entropy is \(-4 \cdot 0.25 \log_2 0.25 = 2.0\) bits per byte. Walker's example of C source code scores about 4.9, implying roughly 38 percent could be saved by compression.

    The mathematics.

    \[H = -\sum_{i=0}^{255} p_i \log_2 p_i, \qquad p_i = \frac{c_i}{n}\]
    • \(c_i\) is the count of byte value \(i\), and \(n\) is the total.
    • ENT attaches no p-value to this figure.

    What it catches and misses. It catches uneven byte use. It is blind to order, since a file holding all 256 values in a neat loop scores a perfect 8. Walker notes that compressors using longer frames may do better than this figure suggests. Note also that this is Shannon entropy, not min-entropy.

    8.3 Chi-square (ENT)¶

    The idea in plain words. Are all 256 byte values equally common, to within what chance allows? Walker calls it the most commonly used randomness test and a very sensitive one. He reads it as a percentage: how often truly random data would exceed this value. Near the middle is good, and very high or very low is bad.

    Example 8.3: Chi-square (ENT)

    Walker's Park and Miller generator example gives 212.53, which random data would exceed 97.53 percent of the time. On 255 degrees of freedom, we get the same figure. His JPEG example gives 1542.26, exceeded less than 0.01 percent of the time, so a dense file is not necessarily a random one.

    The mathematics.

    \[\chi^2 = \sum_{i=0}^{255} \frac{(c_i - n/256)^2}{n/256}, \qquad \text{percentage} = 100 \cdot P\!\left(\chi^2_{255} > \chi^2\right)\]
    • \(c_i\) is the count of byte value \(i\), and \(n\) is the number of bytes.
    • ENT's code sums over 256 cells, which implies 255 degrees of freedom.

    Walker's bands are as follows. Above 99 or below 1 percent is almost certainly not random. Between 95 and 99, or between 1 and 5, is suspect. Between 90 and 95, or between 5 and 10, is almost suspect.

    What it catches and misses. It is sensitive to any uneven use of byte values. Counts that are too even also stand out, at the other end of Walker's scale: the chi-square falls, so the percentage climbs. A perfect loop of 0, 1, 2 ... 255 has chi-square 0, reads as 100 percent and lands in his almost certainly not random band. Like entropy, though, it knows nothing about order: sort a file with ordinary byte counts into ascending order, and the chi-square does not change at all.

    8.4 Arithmetic mean (ENT)¶

    The idea in plain words. Add up all the bytes and divide by how many there are. Random bytes average 127.5. A persistent shift up or down means the values are skewed. It is the simplest of all the checks.

    Example 8.4: Arithmetic mean (ENT)

    The bytes 1, 2, 3, 4, 1, 2, 3, 4 have a mean of 2.5. Walker's JPEG example has 125.93. For a million uniform bytes, the standard deviation of the mean would be only 0.074, so 125.93 would be a long way out for a file that size.

    The mathematics.

    \[\bar{x} = \frac{1}{n} \sum_{j=1}^{n} x_j\]
    • \(x_j\) is byte \(j\).
    • For uniform bytes, the mean is 127.5 and the variance of one byte is \((256^2 - 1)/12\). So \(\bar{x}\) has variance \((256^2 - 1)/(12n)\).
    • ENT prints the mean and gives no p-value.

    What it catches and misses. It catches overall skew. A very skewed distribution that is balanced around 127.5 scores perfectly, as would half the bytes at 0 and half at 255.

    8.5 Monte Carlo value for pi (ENT)¶

    The idea in plain words. Throw darts at a square board with a circle drawn inside. The share landing in the circle should be \(\pi/4\). Using the file's bytes as dart positions, we get an estimate of \(\pi\). If the bytes are lopsided or correlated, the darts miss their mark. It is memorable, but this is a slowly converging test.

    Example 8.5: Monte Carlo value for pi (ENT)

    The six bytes 40 10 05 20 80 20 (in hexadecimal) give \(x = 4198405\) and \(y = 2129952\). Then \(x^2 + y^2 \le (256^3 - 1)^2\), so this is a hit. Walker's 500,000-byte radioactive sample gives 3.143580574, an error of 0.06 percent.

    The mathematics.

    \[\hat{\pi} = 4 \cdot \frac{\text{hits}}{\text{points}}, \qquad \text{a hit if } x^2 + y^2 \le (256^3 - 1)^2\]
    • Each point takes six bytes: three for \(x\) and three for \(y\).
    • ENT prints the estimate and the error percentage, with no p-value.

    Under independent uniform bytes, the hit count is close to binomial, with hit chance near \(\pi/4\). By our calculation, an estimate from 500,000 bytes has a standard deviation of about 0.0057.

    What it catches and misses. It catches gross dependence between successive 3-byte values. It is not a sharp test: only a few of the top bits decide most points, and the error shrinks slowly with data.

    8.6 Serial correlation coefficient (ENT)¶

    The idea in plain words. How much does each byte depend on the one before? For random data, the answer should be close to zero. Walker notes that a C program gives around 0.5, and uncompressed bitmaps approach 1. It is like asking whether today's temperature helps predict tomorrow's.

    Example 8.6: Serial correlation coefficient (ENT)

    For bytes 1, 2, 3, 4 with wraparound, \(n = 4\), \(\sum x_i x_{i+1} = 24\), \(\sum x_i = 10\), \(\sum x_i^2 = 30\). So \(C = (4 \cdot 24 - 100)/(4 \cdot 30 - 100) = -0.2\). His JPEG example scores 0.004249.

    The mathematics.

    \[C = \frac{n\sum_{i} x_i x_{i+1} - \left(\sum_i x_i\right)^2}{n\sum_i x_i^2 - \left(\sum_i x_i\right)^2}\]
    • \(x_i\) is byte \(i\), and \(n\) is the number of bytes.
    • The last byte is paired with the first, a detail we took from ENT's source code.
    • The page points to Knuth for theory and gives no test. In a quick simulation of ours on uniform bytes, the spread of \(C\) was close to \(1/\sqrt{n}\), so a value several times that from zero is unusual.

    What it catches and misses. It catches linear dependence between adjacent bytes. It misses lags other than 1, and relationships that are not linear, so a strong but nonlinear link may give a value near zero.

    8.7 About TestU01¶

    Pierre L'Ecuyer and Richard Simard of the University of Montreal built TestU01 as a C library for testing generators of uniform numbers. Their paper appeared in ACM Transactions on Mathematical Software, and its largest battery is very demanding. It has three batteries for sequences of numbers in \((0, 1)\), shown below, and three more for bit sequences.

    Battery Tests p-values computed Numbers used Time on the paper's 2.4 GHz machine, for MT19937
    SmallCrush 10 not stated as a total slightly under 51,320,000 when run on a file 14 seconds
    Crush 96 144 about \(2^{35}\) 1 hour
    BigCrush 106 160 about \(2^{38}\) 5.5 hours

    The authors suggest starting with SmallCrush, then going on to Crush and BigCrush if everything is fine. Flagging is by reporting, not a fixed level. The batteries print a summary of any p-values outside \([0.001, 0.9990]\), marking values below \(10^{-300}\) as eps and below \(10^{-15}\) as eps1. Very small and very large p-values both count, since a large one can mean excessive uniformity. In their comparison tables, the authors treat a p-value outside \([10^{-10}, 1 - 10^{-10}]\) as a clear failure and values in \((10^{-10}, 10^{-4}]\) or \([1 - 10^{-4}, 1 - 10^{-10})\) as suspect. For a borderline result, you run the test again on fresh numbers until the failure is obvious or the suspicion fades. Since these are large tests on real generators, the small examples below are only toys to show the mechanics. MT19937 is a telling case: the paper reports that it fails only two linear complexity tests, with p-values above \(1 - 10^{-15}\), and that all LFSR and GFSR-type generators fail those two.

    8.8 Birthday spacings (SmallCrush)¶

    The idea in plain words. This is Marsaglia's birthday spacings test at larger scale. Throw points into a huge number of cells, sort their cell numbers and look at the gaps. Generators with a lattice structure give far too many equal gaps. It catches linear congruential generators very fast.

    Example 8.8: Birthday spacings (SmallCrush)

    Cell numbers 1, 4, 9, 16, 20, 25 in a space of 32 cells give gaps 3, 5, 7, 4, 5. The value 5 repeats, so \(Y = 1\), while \(\lambda = 6^3/(4 \cdot 32) = 1.6875\). The real SmallCrush settings give \(\lambda = (5 \times 10^6)^3/(4 \cdot 2^{60}) = 27.1\).

    The mathematics.

    \[Y \sim \mathrm{Poisson}(\lambda) \text{ approximately}, \qquad \lambda = \frac{n^3}{4k}, \qquad k = d^t\]
    • \(n\) is the number of points, and \(k\) the number of cells.
    • \(Y\) is the number of collisions among the gaps.
    • SmallCrush uses \(N = 1\), \(n = 5 \times 10^6\), \(r = 0\), \(d = 2^{30}\) and \(t = 2\).

    The p-value comes from the Poisson tail. With repeats, the total of \(Y\) is compared with Poisson of mean \(N\lambda\).

    What it catches and misses. It catches lattice structure, and the paper shows linear congruential generators with modulus near \(k\) failing at a sample size that grows only as \(k^{1/3}\). Here it reads just the top 30 bits of each number, so defects in the lowest bits can pass.

    8.9 Collision (SmallCrush)¶

    The idea in plain words. Throw \(n\) balls into far more than \(n\) boxes and count how often a ball lands in a box that is already occupied. Too few collisions means the points are too evenly spread, and too many means they are clumped. The authors find this one of the most powerful simple measures.

    Example 8.9: Collision (SmallCrush)

    Eight balls in 16 boxes landing at 3, 7, 3, 1, 7, 9, 2, 3 occupy 5 boxes, so \(C = 3\), against a rough expectation of \(8^2/(2 \cdot 16) = 2\). In SmallCrush, the expected number is about \((5 \times 10^6)^2/(2 \cdot 2^{32}) = 2910\).

    The mathematics.

    \[C = n - W_1, \qquad \mu_c \approx \frac{n^2}{2k}\]
    • \(n\) is the number of balls, \(k\) the number of boxes, and \(W_1\) the number of occupied boxes.
    • \(C\) is asymptotically Poisson with mean \(\mu_c\) when \(\mu_c\) stays moderate, and normal when \(n/k\) tends to a positive constant.
    • SmallCrush uses \(N = 1\), \(n = 5 \times 10^6\), \(r = 0\), \(d = 2^{16}\) and \(t = 2\), so \(k = 2^{32}\).

    What it catches and misses. It catches clumping and excess regularity, even when the deviation is concentrated in a small part of the space. It sees points two numbers at a time, using only 16 bits from each, so it misses defects outside that field.

    8.10 Gap (SmallCrush)¶

    The idea in plain words. Pick a small target zone in \([0, 1)\) and count how many numbers go by between visits. The waits should follow a simple geometric pattern, like waiting for a particular number on a roulette wheel.

    Example 8.10: Gap (SmallCrush)

    With target width \(p = 1/256\), the chance of a gap of 0 is \(1/256 = 0.0039\), and half of all waits run to at least 177 values, since \((255/256)^{177} = 0.500\).

    The mathematics.

    \[P(\text{gap} = s) = p(1-p)^s, \qquad \chi^2 = \sum_{s} \frac{(\mathrm{obs}_s - \mathrm{exp}_s)^2}{\mathrm{exp}_s}\]
    • \(p = \beta - \alpha\) is the width of the target interval \([\alpha, \beta)\).
    • \(s\) is the gap length, with classes grouped as needed.
    • SmallCrush uses \(N = 1\), \(n = 2 \times 10^5\), \(r = 22\), \(\alpha = 0\) and \(\beta = 1/256\).

    What it catches and misses. It catches a generator that revisits a region too regularly, using bits after dropping the first 22. It watches only one small region, so structure elsewhere goes unnoticed.

    8.11 Simple poker (SmallCrush)¶

    The idea in plain words. Deal hands of \(k\) cards from a deck with \(d\) kinds, and note how many distinct kinds each hand holds. Hands holding too few or too many kinds suggest trouble. It tells you whether values spread as they should within short stretches.

    Example 8.11: Simple poker (SmallCrush)

    With \(d = k = 8\), the hand 1, 4, 4, 2, 7, 1, 4, 0 has 5 distinct values. In SmallCrush, with \(d = k = 64\), the average hand has \(64(1 - (63/64)^{64}) = 40.6\) distinct values.

    The mathematics.

    \[P(s) = \frac{d(d-1)\cdots(d-s+1)}{d^k}\,S(k, s), \qquad \chi^2 = \sum_s \frac{(\mathrm{obs}_s - nP(s))^2}{nP(s)}\]
    • \(s\) is the number of distinct values in a hand of \(k\), drawn from \(d\) values.
    • \(S(k, s)\) is the Stirling number of the second kind, the number of ways to split \(k\) cards into \(s\) groups.
    • SmallCrush uses \(N = 1\), \(n = 4 \times 10^5\), \(r = 24\) and \(d = k = 64\).

    What it catches and misses. It catches local lack of variety in a small field of bits, here six bits after dropping the first 24. It only sees how many values occur, not which.

    8.12 Coupon collector (SmallCrush)¶

    The idea in plain words. Collect a set of \(d\) different coupons, drawing one at a time, and note how many draws it takes to get them all. The waiting time has a known pattern. It is exactly like collecting football stickers: the last one or two take much longer than the rest.

    Example 8.12: Coupon collector (SmallCrush)

    With \(d = 16\), the expected wait is \(16(1 + 1/2 + \cdots + 1/16) = 54.09\) draws. With \(d = 4\), working through the states gives \(P(4) = 0.0938\), \(P(5) = 0.1406\) and \(P(6) = 0.1465\).

    The mathematics.

    \[P_{i \to i}(\text{next draw}) = \frac{i}{d}, \qquad P_{i \to i+1}(\text{next draw}) = \frac{d-i}{d}, \qquad \chi^2 = \sum_{s} \frac{(\mathrm{obs}_s - \mathrm{exp}_s)^2}{\mathrm{exp}_s}\]
    • \(i\) is the number of distinct coupons seen so far, and \(s\) is the total length.
    • The probabilities for \(s\) follow from this simple chain, with classes merged as usual.
    • SmallCrush uses \(N = 1\), \(n = 5 \times 10^5\), \(r = 26\) and \(d = 16\).

    What it catches and misses. It catches a generator whose values do not all appear at the right pace, in a 4-bit field after dropping the first 26. It only looks at this small field.

    8.13 MaxOft (SmallCrush)¶

    The idea in plain words. Take \(t\) numbers at a time and keep the largest. The largest of six uniforms has a known distribution, heavily weighted towards 1. Group after group, we check whether the maxima follow that shape. It is like checking that the tallest player on every six-person team has a typical height.

    Example 8.13: MaxOft (SmallCrush)

    From 0.21, 0.84, 0.33, 0.67, 0.08, 0.52 the maximum is 0.84. Then \(F(0.84) = 0.84^6 = 0.351\). A maximum as low as 0.5 has probability only \(0.5^6 = 0.0156\).

    The mathematics.

    \[F(x) = x^t, \qquad \text{chi-square on } d \text{ equal-probability cells, plus an Anderson-Darling test}\]
    • \(x\) is a group's maximum, and \(t = 6\) is the group size.
    • SmallCrush uses \(N = 1\), \(n = 2 \times 10^6\), \(r = 0\) and \(d = 10^5\).
    • The cells are chosen so that each expects exactly \(n/d\) values.
    • The Anderson-Darling test is a relative of the KS test that pays more attention to the tails.

    What it catches and misses. It catches defects in the top of the range and dependence within short groups. Because only the largest value in each group counts, it is less sensitive to the rest.

    8.14 Weight distribution (SmallCrush)¶

    The idea in plain words. Take a block of 256 numbers and count how many land in a chosen interval. That count should have a binomial spread, and we compare many blocks with that shape. The test was proposed by Matsumoto and Kurita.

    Example 8.14: Weight distribution (SmallCrush)

    With \(k = 256\) and interval width \(p = 1/8\), the mean count is 32 with variance 28. A count of exactly 32 has probability 0.0752, and a count of 45 or more has probability 0.0116.

    The mathematics.

    \[W = \sum_{j=1}^{k} I[\alpha \le u_j < \beta], \qquad W \sim \mathrm{Binomial}(k, \beta - \alpha)\]
    • \(u_j\) are uniforms, and \(I\) is 1 when the condition holds and 0 otherwise.
    • A chi-square compares \(n\) values of \(W\) with that law, with classes regrouped so that expected counts are large enough.
    • SmallCrush uses \(N = 1\), \(n = 2 \times 10^5\), \(r = 27\), \(k = 256\), \(\alpha = 0\) and \(\beta = 1/8\).

    What it catches and misses. It catches clumping across a stretch of 256 outputs, in low bits after dropping 27. It only considers one interval and a small field of bits.

    8.15 Matrix rank (SmallCrush)¶

    The idea in plain words. Our old friend, the rank test, this time with a 60 by 60 grid built from 10 bits per number. It is larger than Diehard's, so it can look further for linear links, though it is still short of the size of very long-period generators.

    Example 8.15: Matrix rank (SmallCrush)

    For \(2 \times 2\) grids, the probabilities of rank 0, 1 and 2 are 1/16, 9/16 and 6/16. For \(60 \times 60\) grids, the chance of rank 60, 59, 58 and 57 are 0.2888, 0.5776, 0.1284 and 0.0052.

    The mathematics.

    \[P[R = x] = 2^{x(L+k-x)-Lk} \prod_{i=0}^{x-1} \frac{(1-2^{i-L})(1-2^{i-k})}{1-2^{i-x}}, \qquad P[R = 0] = 2^{-Lk}\]
    • \(R\) is the rank of an \(L \times k\) matrix, with \(1 \le x \le \min(L, k)\).
    • SmallCrush uses \(N = 1\), \(n = 20000\), \(r = 20\), \(s = 10\) and \(L = k = 60\).
    • A chi-square compares observed ranks with these, after merging rare classes.

    What it catches and misses. It catches linear dependence over a span of 3600 bits, in a field of 10 bits from each number. A recurrence with a longer state, such as MT19937, passes at this size.

    8.16 Hamming independence (SmallCrush)¶

    The idea in plain words. Count the ones in a block, then in the next block. If blocks are independent, a heavy block says nothing about the next. We compare how often each pair of weights occurs with what independence predicts. It is like checking whether a good day on the stock market tells you anything about the next.

    Example 8.16: Hamming independence (SmallCrush)

    The blocks 1011 and 0110 have weights 3 and 2, forming the pair \((3, 2)\). For the real block size of \(L = 300\), each weight has mean 150 and variance 75.

    The mathematics.

    \[P(X_i = a, X_{i+1} = b) = \binom{L}{a}\binom{L}{b} 2^{-2L}, \qquad \chi^2 = \sum_{a, b} \frac{(\mathrm{obs}_{ab} - \mathrm{exp}_{ab})^2}{\mathrm{exp}_{ab}}\]
    • \(X_j\) is the Hamming weight of block \(j\), and \(L\) is the block length in bits.
    • Non-overlapping pairs are used, and classes with few expected counts are lumped together.
    • SmallCrush uses \(N = 1\), \(n = 5 \times 10^5\), \(r = 20\), \(s = 10\), \(L = 300\) and \(d = 0\).

    What it catches and misses. It catches dependence between the weights of neighbouring blocks. It reads only weights, so patterns that keep weights independent go unseen.

    8.17 Random walk (SmallCrush)¶

    The idea in plain words. Each bit is a step left or right. We look at many walks of 150 steps and ask several questions. How many steps went right? How far did it reach? How much time did it spend on the right? How often did it come home, and how often did it cross over? Each has an exact answer.

    Example 8.17: Random walk (SmallCrush)

    The steps \(+1, -1, +1, +1, -1, -1, +1, +1\) give positions 1, 0, 1, 2, 1, 0, 1, 2. So \(H = 5\) steps right, \(M = 2\) for the maximum, \(R = 2\) returns to zero, \(C = 0\) sign changes, and \(J = 8\), since the walk is right of zero at all four odd positions.

    The mathematics.

    \[p_{k,y} = P[S_k = y] = 2^{-k}\binom{k}{(k+y)/2} \text{ when } k + y \text{ is even}, \qquad 0 \text{ otherwise}\]
    \[P[H = k] = 2^{-\ell}\binom{\ell}{k}, \qquad P[M = y] = p_{\ell,y} + p_{\ell,y+1}, \qquad P[J = k] = p_{k,0}\,p_{\ell-k,0}\]
    \[P[R = y] = p_{\ell-y,y}, \qquad P[C = y] = 2p_{\ell-1,2y+1}\]
    • \(S_k\) is the position after \(k\) steps, and \(\ell\) is the walk length.
    • \(H\) counts steps right, \(M\) is the maximum, \(J\) is the time on the right, \(R\) counts returns to 0, and \(C\) counts sign changes.
    • TestU01's guide also lists first-passage times \(P_y\).
    • SmallCrush uses \(N = 1\), \(n = 10^6\), \(r = 0\), \(s = 30\) and \(L_0 = L_1 = 150\).

    What it catches and misses. It catches short-range dependence in bits, including linear structure in weak generators. Walks of only 150 steps see nothing further away, so long-memory defects are left to the bigger batteries.

    8.18 About PractRand¶

    PractRand is an open library and toolset for random number generators, with a command-line tester, RNG_test, that reads from standard input. The pages we read describe version 0.94 and do not name the author. Its approach differs from the other batteries in that it does not fix the amount of data in advance. It tests as you feed it, printing a summary at growing lengths, so you learn how much data was needed before a flaw showed. On the core tests other than BRank, the author reports that real failures usually build gradually, so a failure at \(2^{36}\) bytes would typically be foreshadowed by a warning at \(2^{35}\) bytes. Reading the output is simple: look for FAIL. Each line gives a test name, a raw value, a processed value (a p-value, or pass or fail) and an evaluation in words such as normal, unusual, suspicious, very suspicious or FAIL. The evaluation is a complex function, not a fixed cutoff, and both ends of the range count as bad. The target is about one false positive per 300 million result summaries on good generators. The recommended test set contains the five tests below, plus low-bit variants. Its results table lists MT19937 as failing the standard battery at 256 GB, with lengths rounded up to a power of 2. The author ties that failure to the binary rank test, added to the core set in version 0.91. The documentation gives ideas rather than formulas, so we describe only what it supports. For exact statistics, the source code is the reference.

    8.19 BCFN (PractRand)¶

    The idea in plain words. BCFN looks for long-range correlations by counting bits. At each level, it adds up the ones across longer and longer overlapping stretches and checks whether those weights are distributed as they should be. The documentation notes it often catches Fibonacci-style generators that use large lags to pass other tests. It is like watching a river's level averaged over days, then weeks, then months, to see a slow pattern.

    The mathematics. The documentation describes each level as a frequency test on overlapping sets of Hamming weights, and it does not publish the statistic. The basic fact underneath is that the weight of \(m\) independent fair bits is binomial.

    \[W = \sum_{j=1}^{m} b_j, \qquad W \sim \mathrm{Binomial}\!\left(m, \tfrac{1}{2}\right)\]
    • \(b_j\) are the bits of a block, and \(W\) is its Hamming weight.
    • Written BCFN(X,Y), the test's first parameter is the lowest level checked, with 2 recommended. Higher values are faster but can miss shorter-range effects.
    • The second parameter is the base-2 logarithm of its internal table size, typically 10 to 15, depending on the cache.
    • All higher levels are checked as data allows.

    What it catches and misses. It catches long-range linear correlations. BCFN tests with similar first parameters are correlated with each other. It is one test family, and it is not designed for the very short-range effects that FPF and DC6 target.

    8.20 DC6 (PractRand)¶

    The idea in plain words. DC6 is the short-range partner of BCFN. It looks at a few neighbouring integers, takes some information from each, and checks the pattern of weights across them. So it looks for short-range linear correlations, the kind a small mixing step might leave behind.

    The mathematics. Like BCFN, it is a frequency test on overlapping sets of Hamming weights, using the same binomial fact, and the documentation does not publish the statistic.

    • Its parameters set the integer size it works on, how many adjacent integers it correlates, and what information it takes from each.
    • The documentation names the form DC6-9x1Bytes-1 and points to the source functions for recommended values.

    What it catches and misses. It catches short-range linear dependence. The documentation does not list what it misses. As a bit-counting test, it would not be expected to notice structure that keeps the counts balanced.

    8.21 FPF (PractRand)¶

    The idea in plain words. Despite the name, "floating point frequency", it uses integer maths. Roughly, it takes overlapping windows of the stream, treats each as a number, and looks at how that number would be written in floating-point format. It then runs a frequency test on those formats. That focuses on the rare cases with many zero bits up front.

    The mathematics. The documentation describes the approach, with no parameters or formula in the overview we read.

    • The input is overlapping windows of the stream, read as integers.
    • The test is a frequency test on the binary form of their floating-point representations.

    What it catches and misses. It catches very short-range correlations, shorter than DC6, especially those involving many 0 bits. It can be slow at some settings, and it is not aimed at long-range structure.

    8.22 Gap16 (PractRand)¶

    The idea in plain words. Gap16 is a variation on the classic gap test, which measures how long a value takes to come back. Clumped or too-regular returns are the warning sign, just as with waiting times between buses. The name suggests 16-bit values, although the documentation does not spell that out.

    The mathematics. The documentation describes it as a variation on the classic gap test, with no parameters, and gives no further detail. The classic version's gap probability is shown in the TestU01 section above, but we cannot confirm Gap16's exact variant from the documentation. The output names Gap-16:A and Gap-16:B, and the author notes these two are strongly correlated.

    What it catches and misses. It catches irregular returns of values. The documentation gives no more detail, so we leave it there.

    8.23 BRank (PractRand)¶

    The idea in plain words. This is a binary matrix rank test, as seen in Diehard and SP 800-22. What is original is the control logic, which decides when to pull data and what size of matrix to use. Larger matrices can reach longer linear links, at more cost per bit.

    The mathematics. It is a fairly standard rank test, compared against the known rank probabilities given earlier for SP 800-22 and Diehard.

    \[p_r = 2^{r(2M-r)-M^2} \prod_{i=0}^{r-1} \frac{(1-2^{i-M})^2}{1-2^{i-r}}\]
    • \(p_r\) is the probability of rank \(r\) for a square \(M \times M\) grid.
    • The test's one parameter sets how much time per gigabyte goes on rank calculations, on a log scale.
    • Because results are coarse-grained, precise p-values are not possible for many subtests.

    What it catches and misses. It catches linear dependence over large spans, given enough data. The documentation says this is the only PractRand test MT19937 fails, at 256 GB, and calls those failures oddly brittle, since slight variations can let MT19937 pass. Non-linear structure does not show up through rank.

    8.24 Summary¶

    • ENT prints entropy, chi-square, arithmetic mean, a Monte Carlo value of \(\pi\) and the serial correlation coefficient. It needs no fixed amount of data and gives no verdict.
    • ENT's entropy and chi-square are blind to order: a file that cycles through 0 to 255 scores a perfect 8 bits and chi-square 0, though it is totally predictable.
    • TestU01 has batteries for numbers in \((0,1)\) (SmallCrush, Crush, BigCrush) and for bit strings; its power comes from enormous amounts of data, close to \(2^{38}\) numbers for BigCrush.
    • PractRand grows its sample until a flaw shows, reports an evaluation (normal, unusual, suspicious, very suspicious, FAIL) and lists MT19937 as failing at 256 GB through its binary rank test.
    • TestU01 and PractRand find flaws in algorithms. They say nothing about how much entropy a physical source produces.

    8.25 Exercises¶

    1. Compute the ENT entropy of the byte sequence 1, 2, 3, 4, 1, 2, 3, 4. What does the answer imply for compression?

      Answer

      Four values occur equally often, each with probability 0.25, so the entropy is \(-4\times0.25\log_20.25=2.0\) bits per byte. Since 8 bits would be needed if bytes were uniform, a compressor could in principle save up to \(75\%\) of the file.

    2. A file contains each byte value 0 to 255 exactly once and then repeats that block many times. What do ENT's entropy and chi-square report, and why is the file not random?

      Answer

      Every value is equally common, so the entropy is a perfect 8.0 bits per byte, and the chi-square is 0, which ENT reads as 100 percent and "almost certainly not random" because the counts are too even. The file is completely predictable: both statistics look only at byte counts and ignore order.

    3. For the byte sequence 1, 2, 3, 4 with wraparound, compute the serial correlation coefficient from \(C=(n\sum x_ix_{i+1}-(\sum x_i)^2)/(n\sum x_i^2-(\sum x_i)^2)\).

      Answer

      With wraparound the products are \(1\cdot2+2\cdot3+3\cdot4+4\cdot1=24\), \(\sum x_i=10\) and \(\sum x_i^2=30\). So \(C=(4\cdot24-100)/(4\cdot30-100)=-4/20=-0.2\).

    4. Why does PractRand report results at growing lengths instead of one verdict?

      Answer

      It does not fix the amount of data in advance. It tests as data is fed, so you learn how much data was needed before a flaw showed. Real failures usually build gradually, so a failure at \(2^{36}\) bytes is typically foreshadowed by a warning at \(2^{35}\) bytes.

    5. Why can TestU01 and PractRand be a poor fit for a quantum random number generator device?

      Answer

      They get their power from very large amounts of data, which a device may not be able to supply quickly, and a defect in a physical noise source may not need that much data to matter. They find flaws in algorithms; they do not estimate the entropy of a physical source.
