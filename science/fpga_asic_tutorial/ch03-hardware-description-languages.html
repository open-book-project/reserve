    Chapter 3: Hardware Description Languages¶

    A Hardware Description Language (HDL) is a specialised programming language used to describe the structure and behaviour of electronic circuits. Unlike a normal programming language (Python, C++), an HDL describes hardware that exists physically in parallel — thousands of logic gates switching simultaneously, not one instruction at a time.

    HDL is Not a Programming Language — It Is a Circuit Description

    When you write a = b + c in Python, the computer executes that instruction once, sequentially. When you write the same in SystemVerilog as assign a = b + c;, you are describing a physical adder circuit that computes this value continuously, every nanosecond, in hardware. This parallel-by-default nature is the hardest mental shift for newcomers.

    SystemVerilog is the industry-standard for custom chip design at companies like Intel, AMD, Qualcomm, and Apple. It is a superset of Verilog with stronger type checking, rich data types, and built-in assertion support.

    3.2 The Module — SystemVerilog’s Basic Unit¶

    Every hardware block is described as a module. Think of a module as a hardware component with labelled connectors (ports) on the outside and logic on the inside.

    // Module declaration
module my_adder #(
    parameter int DATA_WIDTH = 8    // <-- Configurable parameter
) (
    // Port list --- the "connectors" on the outside
    input  logic                    clk,
    input  logic                    rst_n,
    input  logic [DATA_WIDTH-1:0]   a,
    input  logic [DATA_WIDTH-1:0]   b,
    output logic [DATA_WIDTH:0]     sum,   // 1 extra bit for carry
    output logic                    overflow
);

    // Internal signals (not visible outside)
    logic [DATA_WIDTH:0] sum_int;

    // Combinational logic
    assign sum_int  = {1'b0, a} + {1'b0, b};
    assign overflow = sum_int[DATA_WIDTH];   // Carry out

    // Sequential logic --- register the output
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            sum <= '0;
        else
            sum <= sum_int;
    end

endmodule  // always end with the module name

    3.2.1 Key Concepts in the Example¶

    parameter
    A compile-time constant. Change DATA_WIDTH to 16 and you instantly get a 16-bit adder — the same source code, different hardware. This is called parameterisation and it is how every reusable IP block in this project is written.
    logic
    The preferred signal type in SystemVerilog. It can hold 0, 1, X (unknown), or Z (high-impedance). Use logic everywhere; avoid the older wire/reg split.
    assign
    Describes continuous (combinational) logic. The right-hand side is always evaluated; the left-hand side updates instantly whenever any input changes.
    always_ff
    Describes flip-flop (sequential) logic. The _ff suffix makes the intent explicit to the synthesis tool and to human readers.
    ’0
    SystemVerilog shorthand for a vector of all zeros, regardless of width. Similarly ’1 is all ones.

    3.3 Real Example: The UART 16550 Transmitter¶

    The file rtl-templates/peripherals/uart_16550.sv implements a full UART compatible with the classic 16550 chip. Let’s look at how it uses these concepts together.

    3.3.1 Baud Rate Generator¶

    // Baud rate generator --- divides system clock by (DLL + DLM*256)*16
logic [15:0] baud_div;   // Divisor from software register
logic [15:0] baud_cnt;   // Current count
logic        baud_tick;  // Pulses once per baud period

always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        baud_cnt  <= 16'd0;
        baud_tick <= 1'b0;
    end else if (baud_cnt == baud_div - 1) begin
        baud_cnt  <= 16'd0;
        baud_tick <= 1'b1;   // Strobe for one clock cycle
    end else begin
        baud_cnt  <= baud_cnt + 16'd1;
        baud_tick <= 1'b0;
    end
end

    How it works: If the system clock is 100 MHz and we want 115200 baud, we need to divide by \(\frac{100\,000\,000}{115200 \times 16} \approx 54\). Software writes 54 into the divisor register; the counter rolls over every 54 clocks, generating a baud_tick pulse.

    3.3.2 TX Shift Register¶

    typedef enum logic [2:0] {
    TX_IDLE, TX_START, TX_DATA, TX_STOP
} tx_state_t;
tx_state_t tx_state;

logic [7:0] tx_shift;  // Data being transmitted
logic [2:0] tx_bit;    // Bit counter (0-7)

always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        tx_state <= TX_IDLE;
        uart_txd <= 1'b1;   // UART idle = line high
    end else if (baud_tick) begin
        case (tx_state)
            TX_IDLE:  if (tx_fifo_not_empty) begin
                          tx_shift <= tx_fifo_out;
                          uart_txd <= 1'b0;  // Start bit (low)
                          tx_state <= TX_DATA;
                          tx_bit   <= 3'd0;
                      end
            TX_DATA:  begin
                          uart_txd <= tx_shift[tx_bit];
                          if (tx_bit == 3'd7)
                              tx_state <= TX_STOP;
                          else
                              tx_bit <= tx_bit + 3'd1;
                      end
            TX_STOP:  begin
                          uart_txd <= 1'b1;  // Stop bit (high)
                          tx_state <= TX_IDLE;
                      end
        endcase
    end
end

    This 20-line FSM is the heart of every UART in the world — a standard serialiser that converts a parallel byte into a serial bit stream.

    3.4 The AXI4-Lite Slave Register File¶

    The file rtl-templates/axi-bus/axi4_lite_slave.sv is one of the most important templates in the project. Almost every peripheral in the IP library uses it as its control register interface.

    module axi4_lite_slave #(
    parameter int N_REGS    = 8,
    parameter int DATA_W    = 32,
    parameter int ADDR_W    = 5
) (
    input  logic                clk,
    input  logic                rst_n,
    // -- AXI4-Lite slave ports (36 signals total) --
    input  logic [ADDR_W-1:0]   s_axi_awaddr,
    input  logic                s_axi_awvalid,
    output logic                s_axi_awready,
    input  logic [DATA_W-1:0]   s_axi_wdata,
    input  logic [DATA_W/8-1:0] s_axi_wstrb,
    input  logic                s_axi_wvalid,
    output logic                s_axi_wready,
    output logic [1:0]          s_axi_bresp,
    output logic                s_axi_bvalid,
    input  logic                s_axi_bready,
    // ... (read port omitted for brevity)
    output logic [N_REGS*DATA_W-1:0] reg_out  // All register values
);
    logic [DATA_W-1:0] regs [0:N_REGS-1];

    // Write logic
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            foreach (regs[i]) regs[i] <= '0;
        else if (s_axi_awvalid && s_axi_awready &&
                 s_axi_wvalid  && s_axi_wready) begin
            // Word-addressed index from byte address
            automatic int idx = s_axi_awaddr[ADDR_W-1:2];
            for (int b = 0; b < DATA_W/8; b++)
                if (s_axi_wstrb[b])
                    regs[idx][b*8 +: 8] <= s_axi_wdata[b*8 +: 8];
        end
    end

    // Pack all registers onto output bus
    generate
        for (genvar i = 0; i < N_REGS; i++)
            assign reg_out[i*DATA_W +: DATA_W] = regs[i];
    endgenerate
endmodule

    3.6 Generate Blocks — Hardware for Loops¶

    A generate block creates hardware structures that repeat. Unlike a software loop (which runs N times), a generate loop creates N physical instances simultaneously.

    generate
    for (genvar i = 0; i < N_TAPS; i++) begin : tap_gen
        // Creates N_TAPS independent multiply-accumulate units
        always_ff @(posedge clk)
            delay_line[i+1] <= delay_line[i];

        assign products[i] = delay_line[i] * coeff[i];
    end
endgenerate

    This pattern appears in the FIR filter at rtl-templates/dsp/fir_filter.sv — the generate loop unrolls into N_TAPS parallel multiply-accumulate units.

    3.7 Common Mistakes (and How to Avoid Them)¶

    Table 3.3. Frequent SystemVerilog pitfalls
    Mistake Fix
    Mixing wire and reg Use logic everywhere
    Inferring latches with always_comb Cover all cases in if/case; add default
    Forgetting reset in always_ff Always add if (!rst_n) branch
    Using = (blocking) in always_ff Use <= (non-blocking) in clocked blocks
    Using <= in always_comb Use = (blocking) in combinational blocks
    Bit-width mismatch Use $bits() and explicit casts

    Blocking vs Non-Blocking Assignment

    • a = b + 1; — blocking: executes immediately in sequence (use in always_comb).

    • a <= b + 1; — non-blocking: schedules update at end of time step (use in always_ff).

    Mixing the two inside the same always_ff block causes subtle, hard-to-find simulation bugs.

    3.8 Linting — Your First Quality Gate¶

    Before simulation, always run the linter. This catches typos, width mismatches, and unconnected ports:

    bash scripts/bash/lint_check.sh rtl-templates/

# Or directly with Verilator:
verilator --lint-only -Wall \
    rtl-templates/peripherals/uart_16550.sv

# Expected output for clean code:
# Linting: rtl-templates/peripherals/uart_16550.sv ... PASS

    3.9 Summary¶

    • HDL describes hardware, not a sequence of instructions.

    • A module is the basic unit; ports are its interface.

    • assign = combinational; always_ff = sequential (clocked).

    • parameter makes modules reusable with different widths.

    • generate creates parallel hardware structures.

    • Always lint before simulating; always use non-blocking in always_ff.
